# 推理服务熔断与降级：依赖失效时保住核心路径

推理链路常依赖特征服务、向量库或外部模型。依赖变慢时继续无上限排队，会把局部故障扩散成整个服务不可用。每个调用都应有短于请求总期限的超时，并把连接、首字节和整体耗时分别观测。

熔断器在滚动窗口内根据失败率或慢调用比例打开，暂时拒绝新调用；经过冷却期只放少量探测请求，成功后再恢复。阈值应通过压测与错误预算确定，不能照搬固定数字。重试只用于幂等且可能恢复的错误，并加入退避、抖动与总次数上限。

降级结果要诚实表达能力变化：可返回缓存过且仍在有效期内的答案、缩小候选集、切换轻量模型，或明确提示稍后重试。不能把空证据包装成确定结论。响应中记录降级原因和数据新鲜度，便于前端展示与后续审计。

演练时同时验证依赖超时、部分分区失败和恢复抖动。成功标准不是“主接口仍为 200”，而是核心路径有界、错误可识别、恢复后不会瞬间把积压流量全部打回依赖。
