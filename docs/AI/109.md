# 向量维度契约：在写入前阻止索引错配

更换嵌入模型后，维度、归一化方式和距离度量都可能变化。仅检查数组能否写入不够：同维度的两种模型也不能安全混用，否则检索结果会无声失真。

为每个索引保存契约：嵌入模型及修订版本、向量维度、是否归一化、距离度量、文本预处理版本和创建时间。写入客户端先校验契约，再校验每条向量长度、有限数值和可选的范数范围；不合格记录进入隔离队列，不能用截断或补零“修复”。

查询请求携带相同的嵌入版本标识，服务端拒绝版本不匹配。模型迁移应新建索引、离线回填、双读评测并逐步切流，不能在旧索引上混写。回滚时也要把查询编码器和索引作为一个整体切换。

上线门禁至少包含已知文本的维度检查、相同输入的确定性容差检查，以及固定查询的近邻冒烟测试。契约让错误在写入边界暴露，而不是几天后以“回答变差”的形式出现。
