# RAG 元数据过滤测试：证明权限与条件真的生效

RAG 常按租户、权限、语言、日期或文档状态过滤。最危险的错误不是少召回，而是过滤没有下推到检索阶段，敏感片段已经进入重排或模型上下文。

构造一个最小测试语料：两个租户拥有内容相似但带唯一哨兵词的文档，再加入已过期、草稿和无权限文档。对每种身份查询哨兵词，断言返回集合只包含允许的文档；同时检查检索追踪，确认过滤条件实际传给了向量库或关键词引擎。

测试空列表、多个条件组合、缺失元数据、时区边界和索引更新延迟。默认策略应是拒绝，而不是字段缺失时放行。若后端不支持某种过滤，应用层二次过滤只能作为防线，仍需保证未授权内容不会被发送给外部重排或生成服务。

生产监控记录过滤前后候选数量，但日志只保存文档标识和策略版本，不记录敏感正文。每次权限模型、索引 schema 或检索后端升级，都重跑这组隔离测试。
