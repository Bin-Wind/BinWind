# RAG 延迟预算：拆分检索、重排与生成耗时

只监控端到端耗时，无法知道优化该落在哪里。先从用户可接受的总期限倒推，为查询改写、检索、重排、上下文组装、首 token 和完整生成分别分配预算，并预留网络抖动空间。

每个阶段记录 p50、p95、p99 与超时数，追踪中带上候选数量、过滤结果数、上下文 token 数和模型版本。平均值会隐藏尾延迟；阶段耗时也不能简单相加不同请求的 p99，因此仍需保留端到端分位数。

超预算时优先做有界降级：减少改写分支、限制候选数、跳过收益有限的重排、缩短生成上限，或返回已有证据列表。降级顺序必须通过离线质量评测和线上实验确定，不能只以更快为目标。

压测应覆盖热缓存、冷缓存、稀有过滤条件和后端部分变慢。最终仪表盘既显示速度，也显示检索命中与答案质量，避免把系统优化成快速返回低质量结果。
