# Agent 补偿操作：部分成功后如何安全收尾

跨多个系统的任务很少拥有统一事务。Agent 创建了文件、更新了工单，却在发送通知时失败，简单“从头重试”可能制造重复内容。执行前应把每一步的幂等键、成功证据和可用补偿写入计划。

补偿不是盲目反向调用。删除刚创建的草稿通常可行，但撤回已发送邮件未必可靠；已经被他人修改的记录也不能覆盖回旧值。每个工具应返回稳定资源 ID、版本号和当前状态，补偿时用条件更新确认对象仍处于预期版本。

失败后先读取真实外部状态，再决定继续、补偿或人工接管。日志将步骤标为未开始、结果未知、已确认成功或已补偿；网络超时属于“结果未知”，必须用幂等键查询，不能直接当失败重发。

演练需覆盖在每个步骤后中断，并验证重复执行不会扩大影响。若某一步不可补偿，就把它放到流程末端并增加审批，把前置检查做到足够充分。
