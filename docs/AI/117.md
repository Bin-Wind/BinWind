# 推理运行时兼容矩阵：升级前验证模型、驱动与量化格式

同一个模型文件在不同 GPU、驱动、CUDA、推理引擎和量化后端上，可能表现为无法加载、吞吐下降或输出漂移。升级不能只看“服务启动成功”，应维护一张可执行的兼容矩阵。

## 矩阵包含什么

每一行代表一个实际部署组合：模型摘要、量化格式、推理引擎版本、容器镜像摘要、GPU 型号、驱动和关键启动参数。不要只记 `latest` 或大版本号；镜像与模型都使用不可变摘要。

为组合定义四类检查：能否加载、固定输入输出是否满足容差、目标并发下延迟与显存是否达标、长时间运行是否稳定。生成模型不要要求逐字相同，可在固定采样参数下比较结构约束、拒答行为和任务指标。

## 最小探针集

探针应覆盖短输入、接近上下文上限的输入、批处理、流式输出、工具调用结构以及非 ASCII 文本。每条用例保存输入、参数、预期不变量和允许误差，不把真实敏感数据放进测试包。

```json
{
  "case": "json_schema",
  "max_tokens": 64,
  "temperature": 0,
  "assert": ["valid_json", "required_keys:name,score"]
}
```

## 升级顺序

先在隔离节点跑完整矩阵，再用影子请求验证真实分布，最后只给少量可回退流量。一次只改变一个主要变量；同时升级驱动、引擎和模型会让回归原因无法定位。

兼容结论要有失效日期。新增 GPU、驱动补丁或引擎版本后，只补测受影响组合。若旧稳定组合已无法在新节点恢复，就不能把它写进回退计划。
