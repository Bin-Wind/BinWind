# 微调优化器状态：恢复训练时不能只加载权重

检查点里的模型权重回答“参数现在是多少”，优化器状态则保存动量、二阶矩估计等训练历史。若恢复时只加载权重，训练虽然能继续跑，更新轨迹却会突然改变；学习率调度器和随机数状态缺失也会破坏可比性。

## 完整检查点

可恢复检查点通常包含模型或适配器权重、优化器、学习率调度器、梯度缩放器、全局步数、随机数状态和数据采样位置。还要记录代码提交、依赖锁文件与训练配置。分布式训练需要确认保存和恢复工具是否支持当前分片策略。

## 做一次中断实验

不要等故障时才验证。用小数据运行 N 步并保存，重新启动后再跑 M 步；与连续运行 N+M 步比较损失、学习率、样本顺序和最终参数摘要。在允许非确定性的硬件上设定容差，而不是追求无法保证的逐位一致。

```python
checkpoint = {
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "scheduler": scheduler.state_dict(),
    "step": step,
    "torch_rng": torch.get_rng_state(),
}
torch.save(checkpoint, "checkpoint.pt")
```

实际项目还应保存 CUDA 随机状态和数据加载器进度；不要把简化示例直接当成分布式方案。

## 哪些变化不能无条件续跑

修改参数分组、优化器类型、世界大小、批次定义或数据顺序后，旧状态可能不再兼容。此时应明确选择“精确恢复”还是“从权重热启动”，并为后者重新预热、标记新的实验分支。

验收恢复时，不只看第一步没有报错，还要检查学习率、全局步数、首批样本 ID 和若干步后的损失连续性。
