# 微调梯度累积尾批次：不足步数时如何正确更新

梯度累积把多个微批次合成一次参数更新。若一个 epoch 的微批次数不能整除累积步数，末尾“尾批次”很容易被丢弃，或仍按完整累积数缩放，造成样本利用率与梯度尺度偏差。

## 先定义更新语义

假设累积 4 个微批次。常规组的每个 loss 除以 4 后反向传播；若最后只剩 2 个微批次，要么明确丢弃并记录，要么按 2 重新缩放后更新。两种都可解释，但不能静默发生。

```python
from itertools import islice

iterator = iter(loader)
while True:
    group = list(islice(iterator, accum_steps))
    if not group:
        break

    optimizer.zero_grad(set_to_none=True)
    group_size = len(group)
    for batch in group:
        loss = compute_loss(batch) / group_size
        loss.backward()
    optimizer.step()
```

示例在反向传播前取得整组，因此尾批次能使用实际组大小。它为讲清语义把微批次暂存在列表中；生产环境可用框架提供的累积器，或在已知数据加载器长度时预先计算尾组大小。

## 分布式与调度器

分布式训练中，各 rank 必须执行相同次数的同步更新，否则可能挂起。学习率调度器按 optimizer step 推进，而不是每个微批次推进。日志同时记录微批次、更新步和有效样本数，避免图表横轴混淆。

## 回归测试

构造 10 个微批次、累积 4 步的测试，预期是 3 次更新或明确的 2 次更新加 2 批丢弃。再检查每次更新覆盖的样本 ID 和权重变化。尾批次越小，梯度方差越大；必要时跨 epoch 累积，但要处理数据边界和可恢复进度。
