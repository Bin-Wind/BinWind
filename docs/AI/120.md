# 微调评测生成配置：把温度、停止词与长度一起锁定

同一检查点使用不同温度、最大生成长度或停止条件，评测分数可能显著变化。若每次实验从服务默认值读取配置，就无法判断改进来自训练还是解码。

## 建立版本化评测配置

配置至少固定提示模板、分词器版本、最大输入与输出长度、采样开关、温度、top-p、停止序列和随机种子。确定性解码时应关闭采样；不是把温度写成 0 就假定所有框架行为一致。

```yaml
evaluation_id: support-v3
prompt_template: chatml-v2
do_sample: false
max_new_tokens: 256
stop:
  - "<|end|>"
seed: 20260917
```

保存模型实际接收的渲染后文本，以及原始输出和解析结果。这样模板或解析器变化时，可以区分模型失败与评测工具失败。

## 防止长度制造假象

截断输入会丢证据，输出上限太短会把正确答案截断；上限过长又可能增加跑题和成本。报告应分别统计输入截断率、因长度结束的输出比例和有效答案长度分布，而不是只给一个准确率。

结构化任务要将“JSON 无法解析”“缺字段”和“字段值错误”分开。自由文本任务若使用模型裁判，也要固定裁判版本、提示词和位置随机化规则，并保留人工抽检。

## 公平比较

所有候选检查点先跑同一冻结配置。若要为模型单独调解码参数，应在独立开发集完成，并把调参成本与搜索空间写入结果。最终测试集只运行预先选定的配置，避免用测试分数反向挑参数。
