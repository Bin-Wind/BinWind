# RAG 稳定切片 ID：文档小改动后只更新真正变化的块

若切片 ID 使用数组下标，文档开头插入一句话会让后续所有 ID 改变，增量索引退化成全量删除与重建。稳定 ID 的目标，是让相同内容在合理编辑后保持身份，同时让真实变化可检测。

## ID 的组成

可用规范化文档 ID、结构路径和内容摘要组合。结构路径来自章节标题层级，不依赖“第 7 块”这样的全局位置；内容摘要对规范化后的切片文本计算。保留原始文本用于展示，不要用过度规范化后的文本回答。

```python
from hashlib import sha256

def chunk_id(document_id: str, heading_path: str, text: str) -> str:
    normalized = " ".join(text.split())
    raw = f"{document_id}\0{heading_path}\0{normalized}".encode("utf-8")
    return sha256(raw).hexdigest()[:24]
```

截短摘要有碰撞概率；索引量大或风险高时保存完整摘要，并对同 ID 不同内容做冲突检查。

## 更新算法

新旧版本分别产生 `{chunk_id: metadata}`。集合差得到新增、删除与保持项；先写新增块并验证，再删除旧块，可减少更新窗口中的空洞。若权限或来源 URL 改变，即使正文没变也必须更新元数据。

标题改名会改变其下所有结构路径。可为章节维护稳定内部 ID，或接受该范围重建；选择取决于编辑频率与实现复杂度。

## 验收

用三类变更测试：修正一个错字只更新相关块，在开头插段不重建无关章节，删除章节会移除对应向量。最后查询已删除句子，确保它不再从向量索引、关键词索引或缓存中出现。
