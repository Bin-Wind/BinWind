# RAG 引用片段绑定：让答案句子能定位到原文证据

只在答案末尾列几个文档链接，并不能证明每个结论由哪段原文支持。更可核验的设计，是让答案中的事实性句子绑定到稳定片段 ID 与原文偏移，并在展示时高亮对应证据。

## 检索结果携带定位信息

每个切片保存文档版本、片段 ID、起止字符偏移、章节路径和来源地址。偏移必须针对一个明确版本；源文档更新后，旧偏移不能套到新文本上。

```json
{
  "claim": "标准保修期为两年。",
  "citations": [
    {"chunk_id": "warranty-a91f", "start": 128, "end": 141}
  ]
}
```

模型可以提出引用，但服务端负责校验 ID 存在、偏移没有越界、引用片段确实来自本次允许使用的上下文。不要让模型自行拼接任意 URL。

## 处理一个结论多份证据

一句话包含多个可验证主张时拆句，或为每个主张提供独立引用。冲突来源应展示差异和版本时间，不能只选择最顺眼的一条。推断性结论要明确标记“基于这些证据推断”，与原文事实分开。

## 评测引用质量

抽样检查三个指标：覆盖率——重要结论是否有引用；正确性——引用是否支持该结论；可定位性——用户能否打开并看到对应版本与高亮。链接可用但证据不支持，仍是失败。

权限校验必须在打开引用时再次执行。答案被分享给无权限用户时，应隐藏受限证据和由其支持的结论，而不只是让链接返回 403。
