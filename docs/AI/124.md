# Agent 持久工具收件箱：进程重启后仍能接住异步结果

外部导出、视频渲染或批处理可能几分钟后才完成。若 Agent 只在内存中等待回调，进程重启就会丢失结果；不断轮询又浪费配额。持久工具收件箱把“提交任务”和“消费结果”拆成可恢复的两步。

## 提交时先落账

为每次工具任务生成稳定 `job_id`，先写入数据库，再调用外部服务。记录请求摘要、调用方、截止时间和幂等键。外部服务接受幂等键时，重试提交不会创建两个任务。

状态可限定为 `pending`、`running`、`succeeded`、`failed`、`expired`。状态转移使用条件更新，避免两个工作进程同时把同一结果交给 Agent。

```sql
UPDATE tool_jobs
SET status = 'succeeded', result_ref = :result_ref
WHERE job_id = :job_id
  AND status IN ('pending', 'running');
```

## 回调只存引用

验证回调签名、时间戳和任务 ID 后，将大型结果存入受控对象存储，收件箱只保存摘要与引用。回调重复到达应返回成功但不重复触发后续动作。未经验证的回调不能改变任务状态。

## Agent 如何恢复

每次恢复从检查点读取未完成 `job_id`，查询收件箱而不是重新提交。成功结果先校验类型、大小与摘要，再进入推理；失败和过期按预设策略重试、降级或请求人工处理。

定期清理已消费结果，但审计记录按策略保留。测试应覆盖回调先于等待、重复回调、进程在状态更新前后崩溃，以及结果到达时原任务已取消。
