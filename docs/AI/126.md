# Agent 策略决策日志：记录为什么允许、拒绝或升级

权限日志若只写“调用成功”，无法解释某次动作为什么被允许。策略决策日志应记录输入事实、命中的规则和结果，让安全审计与误拒排查都能复现，同时避免泄露提示词和敏感凭证。

## 一条决策需要什么

记录决策 ID、时间、主体、动作、资源、策略版本、结果与理由码。输入上下文只保存经过最小化的属性，例如角色、资源分类和风险等级；令牌、完整文档和用户秘密不进入日志。

```json
{
  "decision_id": "dec_01",
  "subject": "agent:invoice-helper",
  "action": "invoice.send",
  "resource": "invoice:masked",
  "policy_version": "2026-09-17.3",
  "result": "require_approval",
  "reason": "external_side_effect"
}
```

理由码应稳定、可统计，面向用户的解释可以另行生成。不要记录模型的整段内部推理；审计需要的是可验证事实与规则路径。

## 把决策与执行串起来

执行请求携带决策 ID 和短期授权令牌。工具端再次验证动作、资源、有效期与一次性约束，防止允许“预览发票”的结果被挪用到“发送发票”。决策后资源状态变化时应重新评估。

## 回放与告警

策略发布前，用历史去敏决策在新版本上回放，统计由允许变拒绝、由审批变自动的差异。对高风险自动允许、未知策略版本和日志写入失败设置告警；无法写审计日志时，高风险动作应默认停止。

保留期限和访问权限按组织政策设置。定期抽样从决策日志追到实际工具调用，确认“记录允许”与“执行了什么”一致。
