# 线上特征回退：实时特征失效时退回安全基线

模型依赖实时余额、近七日行为等特征时，特征服务超时不应直接变成全站故障。回退设计要在上线前确定“缺什么时用什么”，而不是故障中临时填零。

## 给特征分级

把输入分为必需、可回退和仅增强三类。身份、币种等必需特征缺失时拒绝推理；可回退特征可使用带时间戳的最近值；仅增强特征可删除并切换到专门训练过的降级模型。零值只有在业务上确实表示零时才安全，不能用它代替未知。

```python
def choose_feature(live, cached, now, max_age):
    if live is not None:
        return live, "live"
    if cached and now - cached["updated_at"] <= max_age:
        return cached["value"], "cached"
    raise ValueError("required feature unavailable")
```

## 让模型见过回退输入

若训练时所有字段都完整，线上突然加入缺失标记或旧值，分布会改变。训练与评测数据应覆盖实际回退状态，并把特征来源、年龄和降级模式作为可观测信息。降级模型要独立版本化，不能假设主模型自然兼容缺列。

## 演练恢复

在预发环境注入超时、陈旧缓存和部分字段缺失，验证延迟上限、预测质量与告警。恢复实时服务后逐步切回，避免缓存同时失效形成尖峰。监控要区分实时命中率、缓存年龄和拒绝比例，才能判断系统是在正常服务还是悄悄长期降级。
