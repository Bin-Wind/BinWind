# 模型服务金丝雀判定：用配对请求减少流量噪声

新旧模型若分别接收不同用户，输入难度差异会掩盖真实质量变化。金丝雀阶段可对一小部分请求做配对评测：旧模型继续回答用户，新模型在影子路径处理同一份规范化输入，再逐请求比较。

## 先定义判定单元

记录请求 ID、模型版本、提示模板、检索版本、生成配置和时间窗口。随机生成任务还要固定种子或使用多次采样的汇总指标。比较时按请求配对计算延迟差、成本差和质量差，而不是只比较两组总体均值。

```python
paired = [new - old for old, new in zip(old_scores, new_scores)]
mean_delta = sum(paired) / len(paired)
win_rate = sum(delta > 0 for delta in paired) / len(paired)
```

质量评分可来自确定性规则、人工盲评或经校准的评审模型，但关键样本不能只靠单一自动评分。安全违规、空答案和结构化输出失败应作为独立硬门槛。

## 控制影子路径副作用

新模型不得重复发送邮件、写数据库或调用收费工具；工具调用应使用只读模拟器或明确隔离环境。含敏感数据的请求必须沿用生产访问控制与保留策略。

达到预设样本量和置信要求后再扩大真实流量。若不同语言、客户层级或任务类型表现相反，应分层判定，不能用总体平均掩盖关键人群退化。所有阈值在实验前写入发布计划，避免看完结果再移动标准。
