# 训练任务资源配额：让失败尽早而不是挤垮集群

训练任务同时申请 GPU、CPU、内存、临时磁盘和网络带宽。只限制 GPU 数量，仍可能因数据加载器占满内存或检查点写爆磁盘，拖累同一节点的其他任务。

## 从一次可复现试跑估算

先用代表性批次运行短任务，记录峰值显存、主机内存、数据读取速率、检查点大小和保存耗时。按模型并行方式换算每个工作进程的资源，再留出明确余量。请求值用于调度，限制值用于隔离；二者相差过大既浪费容量，也会让突发占用难以预测。

作业提交前校验：GPU 数是否能被并行规模整除，临时盘是否容得下至少一个完整检查点及写入中的副本，预计训练时间是否超过队列上限。条件不满足就快速失败并给出可行动原因。

## 公平共享与抢占

按团队或项目设置总配额，交互实验与长训练使用不同队列。低优先级任务允许抢占时，训练代码必须能从最近的完整检查点恢复；保存过程使用临时名并在校验后原子发布，不能把半个检查点当成可恢复状态。

## 观察实际使用

持续比较申请量、峰值和平均使用率。长期只用到一半的资源应下调请求，频繁接近限制则需优化或扩大配额。OOM、磁盘满和排队时间要分别统计，避免把所有失败都归因于“GPU 不够”。
