# 微调数据难例配比：别让少数边界样本被平均掉

客服升级、合规拒答或罕见格式往往只占很小比例，却决定系统能否安全上线。把所有样本均匀混洗，难例的训练信号可能被常见任务淹没；简单复制难例又容易过拟合。

## 先把“难”定义成标签

按失败原因标注类别，例如长上下文、相似意图、拒答边界和严格 JSON。标签应来自可复现规则或评审记录，而非“看起来复杂”。训练、验证和测试都按实体或时间切分，再检查每个难例类别是否有足够独立样本。

可通过分层采样设定目标占比，但保留原始数据分布的评测集。训练日志同时记录自然分布指标和难例指标，防止总体上涨掩盖边界退化。

```python
weights = {"common": 1.0, "long_context": 2.0, "safety_edge": 3.0}
sample_weight = [weights[row["bucket"]] for row in rows]
```

权重只是示意，实际数值应通过小规模对照实验确定。重复采样时要统计唯一样本覆盖率，避免同一条记录在一个 epoch 中出现过多次。

## 设定退出条件

若难例提升伴随常见任务明显下降，应检查标签冲突、模板差异和容量，而不是继续加权。最终报告每类样本数、采样后占比、实体重叠检查和分层置信区间，让“难例已经改善”有可审计证据。
