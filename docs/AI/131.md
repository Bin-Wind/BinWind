# LoRA 多适配器路由：加载、隔离与回退

同一基础模型可挂载面向不同客户或任务的 LoRA 适配器，但路由错误会把错误语气、知识或权限带给用户。适配器选择必须是受控配置，不应让任意请求直接提供文件路径。

## 建立适配器注册表

每个适配器记录稳定 ID、基础模型摘要、训练模板、目标模块、版本、状态和允许租户。加载前验证基础模型与目标层完全兼容，并校验文件摘要。处于草稿、撤回或不兼容状态的版本不能进入生产路由。

路由结果应由已认证的租户、任务类型和发布规则共同决定。默认路径使用经过验证的通用适配器或基础模型，不把“找不到配置”静默映射到另一个客户。

## 控制缓存与并发

适配器缓存设置容量和淘汰策略；正在处理请求的版本保持引用，不能在推理中途卸载。首次加载要有超时与并发合并，避免一批相同请求重复读取同一权重。日志记录适配器 ID 和版本，但不泄露客户数据。

## 回退必须可评测

基础模型不一定是安全回退，因为它可能缺少格式与领域约束。为每条路由预先定义回退版本，并用同一回归集验证。发布时先预热新适配器、小流量切换，出现加载错误、延迟或质量门禁失败时按版本快速退回。
