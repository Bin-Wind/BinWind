# RAG 删除一致性：文档撤回后同步清理切片与缓存

源文档被删除或权限撤回后，只从文件列表移除标题并不够。向量切片、关键词索引、答案缓存和离线副本仍可能继续返回旧内容，形成合规与信任风险。

## 用文档身份驱动删除

为源文档分配稳定 `document_id`，每个切片保存该 ID、源版本和权限版本。删除事件携带目标版本与幂等键，由各下游分别确认处理。不要只按标题删除，因为标题可重复且会变化。

```sql
DELETE FROM chunks
WHERE document_id = :document_id
  AND source_version <= :withdrawn_version;
```

条件版本可防止延迟到达的旧删除事件误删后来重新发布的内容。物理删除前若需软删除，检索查询必须默认过滤不可见状态，且失败时选择拒绝返回而不是放宽过滤。

## 清理所有派生物

维护数据血缘清单：向量库、倒排索引、重排缓存、答案缓存、评测样本和备份分别有何保留规则。缓存键中包含知识库版本，撤回时提升版本或定向失效；仅等待 TTL 过期可能不满足删除时限。

定期用“墓碑探针”搜索已撤回文档的独特短语，确认所有线上路径都不再命中。记录事件产生、各系统确认和最终验证时间。删除失败进入可重试队列并告警，不能因一个后端暂时不可用就标记任务完成。
