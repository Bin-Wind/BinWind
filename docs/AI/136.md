# Agent 工具能力探测：调用前确认版本与权限

工具名称相同，不代表当前环境支持相同参数、权限或返回格式。Agent 若凭旧记忆直接调用，常在长任务中途才发现缺少导出能力或只有只读权限。

## 把探测变成显式步骤

任务开始时读取工具清单、Schema、版本和授权范围，只探测完成当前任务所需的能力。对“能否写入”“是否支持幂等键”“最大批量”等关键条件形成结构化快照，并与计划绑定。

探测调用应无副作用，例如读取元数据或执行官方 dry-run。不能通过创建再删除对象来试权限；删除可能失败，也会污染审计记录。若服务不提供能力端点，使用配置清单并在首次真实调用前保留安全检查。

## 防止执行途中漂移

长任务记录探测时间和版本。工具返回不兼容错误或权限撤销时，停止相关分支、刷新能力快照，再重新规划；不要无限重试同一参数。恢复任务时也要重新探测，因为旧检查点只能证明过去状态。

## 让降级可解释

为缺失能力预先定义替代方案，例如无法批量写入时改为有限并发单条写入；若替代会改变结果、成本或外部副作用，则请求人工确认。最终交付中注明实际使用的工具版本和受限能力，避免把降级结果冒充完整完成。
