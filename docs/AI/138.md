# Agent 输出契约：让最终结果可校验可交付

Agent 返回一段“已经完成”的自然语言，不足以让下游判断文件、数据或外部动作是否真的符合要求。输出契约应在执行前定义必需字段、证据和允许的部分完成状态。

## 区分结果与说明

结果字段保存机器可检查的信息，例如状态、产物引用、校验摘要、验证命令和失败项；说明字段再用自然语言概括。状态使用有限枚举，不能同时写“成功”又在备注中藏着未完成步骤。

```json
{
  "status": "completed",
  "artifacts": [{"path": "report.csv", "sha256": "..."}],
  "checks": [{"name": "row_count", "passed": true}],
  "remaining": []
}
```

Schema 只验证形状，业务验证还要确认路径位于授权范围、摘要与实际文件一致、外部对象可读取且版本正确。敏感令牌和完整个人数据不应进入交付结构。

## 明确部分成功

批量任务要列出成功、失败和未尝试对象，并保持稳定标识。若关键门禁失败，状态应是 `failed` 或 `needs_review`，不能用较高完成比例覆盖。重试时消费这些标识，不重新执行已经确认的副作用。

契约版本随任务类型一起保存。新增可选字段可向后兼容，删除或改义则升级主版本。最终自然语言摘要由结构化结果生成，使人看到的结论与机器验收使用同一事实来源。
