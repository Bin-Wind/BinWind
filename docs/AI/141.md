# 模型服务冷启动预算：提前加载而不是让首批请求等待

模型服务扩容时通常要下载权重、分配显存、编译计算图并预热缓存。只监控稳定态延迟，会让新实例通过健康检查后把几十秒等待转嫁给首批用户。

## 拆开冷启动阶段

分别记录镜像启动、权重获取、模型加载、预热请求和进入就绪状态的耗时。权重应按内容哈希缓存，缓存命中与未命中分别统计；预热输入要覆盖实际会用到的主要长度和功能，但不能包含真实用户数据。

就绪探针只在模型完成预热且能够执行一次轻量推理后返回成功，存活探针则只判断进程是否需要重启。混用两者会在加载期间反复杀死正常实例。

## 把时间写进容量计划

若高峰增长速度快于实例冷启动速度，仅靠自动扩容永远追不上。保留预热容量，按队列深度与到达率提前扩容，并限制同时加载的实例数，避免共同争抢网络和存储。

发布新版本时从一个实例开始，观察加载峰值内存和首次请求延迟。回滚也必须验证旧权重仍在可访问位置。冷启动预算的完成条件不是进程出现，而是实例在规定时间内真正具备接流能力。
