# 微调分词器变更：扩充词表后的权重与兼容性

为领域符号增加 token 可以缩短序列，但修改分词器不只是更新一个 JSON 文件。词表大小改变后，模型输入嵌入和输出头必须同步扩展，训练与部署也必须使用同一份分词器。

## 先量化收益

在代表性语料上统计目标术语当前被拆成多少 token，再评估新增词能节省的长度。只为少量样本扩词，可能不值得承担模型兼容成本。新增项要避免与已有特殊 token 冲突。

```python
added = tokenizer.add_tokens(["<DOMAIN_CODE>"])
if added:
    model.resize_token_embeddings(len(tokenizer))
assert model.get_input_embeddings().num_embeddings == len(tokenizer)
```

新增嵌入通常从随机或统计初始化开始，需要足够样本学习；若输出头未与输入嵌入绑定，还要确认两边都已调整。保存时把分词器、特殊 token 映射和模型作为不可拆分产物。

## 做兼容性回归

比较变更前后普通文本的 token ID，未涉及新词的输入不应无故改变。部署前用目标运行时加载产物，验证词表长度、特殊 token ID 和一次生成。旧服务若只更新权重不更新分词器，应直接阻止启动，而不是让索引越界或悄悄使用错误切分。
