# 微调结束符审计：避免模型学不会停下来

微调模型持续生成、吞掉下一轮角色标记，常见原因不是解码器失灵，而是训练样本没有一致的结束边界，或结束 token 被标签掩码排除。

## 检查样本边界

先明确每个回答由哪个 token 结束，聊天模板是否自动追加它，以及多轮样本的角色分隔符是否唯一。对一批格式化样本直接查看末尾 token ID 与监督标签，不要只看渲染后的字符串。

```python
ids = tokenizer.apply_chat_template(messages, tokenize=True)
assert ids[-1] == tokenizer.eos_token_id
assert labels[-1] == tokenizer.eos_token_id
```

如果模板使用专用的“回合结束”标记，它未必等于通用 EOS；此时训练标签和推理 `eos_token_id` 必须共同包含正确边界。Padding token 也不应被误当成结束信号。

## 用停止行为评测

建立短答、长答、多轮和包含类似分隔文本的用例，记录自然结束比例、超长截断比例与结束前内容完整性。不能通过极小的最大生成长度掩盖问题。修正模板后要重新生成训练缓存，旧 token 化数据不会自动更新。
