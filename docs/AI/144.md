# LoRA 适配器精度转换：保存前后验证数值偏差

为了减小体积或匹配部署环境，LoRA 适配器可能从 FP32 转成 BF16 或 FP16。转换看似只是 dtype 变化，但错误的基础模型、缩放系数或保存流程会让产物能加载却输出异常。

## 保留可追踪的源产物

先保存训练完成的原始适配器，并记录基础模型精确版本、目标模块、rank、alpha 与框架版本。转换在副本上进行，不覆盖唯一的高精度检查点。

对每个张量记录名称、形状、原 dtype 和转换后的 dtype，确认没有遗漏或意外转换整数元数据。FP16 的动态范围比 BF16 小，极端权重更需要检查溢出与零化。

## 比较合并前后的行为

用固定基础模型分别加载原始与转换适配器，在一组代表性输入上比较 logits 或任务指标。可计算最大绝对误差和余弦相似度，但最终门槛应来自业务可接受的输出变化。

转换后再执行一次保存—重新加载—推理，排除内存中正确、落盘后缺字段的问题。部署清单必须把适配器与基础模型绑定；只验证文件能打开，无法证明它加载到了预期层，也无法证明数值精度仍合格。
