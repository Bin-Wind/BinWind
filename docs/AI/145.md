# RAG 查询日志脱敏：保留评测价值而不泄露原文

RAG 查询常包含姓名、订单号、内部项目名甚至粘贴的文档原文。完整记录虽然方便排障，却会把检索系统变成新的敏感数据仓库。

## 从用途反推字段

质量评测通常需要查询类别、长度、命中文档 ID、分数、过滤条件和用户反馈，不一定需要长期保存原句。原始查询仅在明确用途、短保留期与严格权限下存储；分析日志使用不可逆请求 ID，并删除认证令牌和完整文档片段。

规则脱敏可以覆盖邮箱、电话等格式，但无法识别所有上下文敏感信息。把自动检测当作一道防线，而不是“日志已安全”的证明。需要关联同一实体时，可使用带密钥的 HMAC，而不是可被字典反推的普通哈希。

## 验证删除与访问路径

分别测试应用日志、检索追踪、错误平台和数据仓库，确保同一查询不会在旁路留下副本。限制导出和全文搜索权限，记录谁访问过原始内容。

保留策略应能实际执行：到期删除索引、缓存和备份引用，并用抽样查询验证不可再检索。脱敏方案上线前用合成敏感样本做回归，避免字段改名后保护规则静默失效。
