# RAG 重排候选池：别让召回上限锁死最终质量

重排器只能调整已经召回的文档。如果相关证据从未进入候选池，再强的模型也无法把它排到前面；但候选过多又会增加延迟和费用。

## 分开测召回与重排

用带相关文档标注的问题，分别计算候选池的 Recall@K 与重排后的 nDCG、MRR 或最终命中率。逐步增加 K，画出召回增益与重排延迟，而不是凭经验固定为 20。

混合检索时先为关键词与向量通道保留独立配额，再去重合并，避免一个通道占满候选。对短实体查询、自然语言问题和带过滤条件的问题分别调参，它们的最佳池大小可能不同。

## 设动态上限

高置信度精确命中可使用小候选池；查询模糊或多个通道分歧较大时再扩大。所有路径仍要有硬上限和总延迟预算。

上线时监控“相关文档未召回”与“已召回但被重排压低”两类错误。前者应调整索引、查询或 K，后者才是重排器问题。把两者混在一个最终准确率里，会让优化方向持续跑偏。
