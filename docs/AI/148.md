# Agent 重试预算传播：避免多层重试放大请求

Agent、工具客户端和下游 SDK 若各自重试三次，一次动作最坏可能扩成数十次外部请求。超时故障中，这种重试风暴会进一步压垮依赖服务。

## 只设一个总预算

任务入口创建截止时间和最大尝试次数，每层调用都接收剩余预算。下游只在剩余时间足以完成一次请求时重试，并把已经尝试的次数返回上层。

```python
def may_retry(attempt, max_attempts, now, deadline, min_time):
    return attempt < max_attempts and deadline - now >= min_time
```

连接超时、限流和明确的临时错误可以有限重试；参数错误、权限拒绝和确定性业务失败应立即停止。带副作用的动作只有在提供幂等键或能确认前一次未执行时才可重试。

## 让退避服从截止时间

指数退避加入随机抖动，但休眠不得越过总截止时间。记录根请求 ID、每次尝试、错误类别和剩余预算，才能看见放大倍数。故障演练中让依赖持续超时，验证 Agent 会在预算耗尽时给出可解释的失败，而不是无限规划新步骤。
