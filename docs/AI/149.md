# Agent 工具演练模式：预览副作用再正式执行

删除文件、发送消息或修改云资源前，Agent 应能展示“将改变什么”。演练模式不是一句提示词，而是工具协议中的明确能力。

## 返回可审阅的计划

工具接收 `dry_run=true` 时，完成权限检查、目标解析和参数验证，但不执行副作用；返回规范化目标、预计变更、风险、不可逆部分与计划指纹。正式调用携带这个指纹，工具再次解析当前状态，状态变化则拒绝执行并要求重新预览。

演练不能调用本身有副作用的探测接口，也不能承诺无法准确预测的结果。对于发送邮件，可预览收件人、主题与附件哈希；对于数据库迁移，可展示语句与影响估计，但不能伪称精确行数。

## 防止模式形同虚设

在工具实现层测试 dry-run 不产生写入、消息和计费调用，不能只依赖 Agent 自觉。日志明确区分预览与执行。高风险动作仍需人工批准，批准内容绑定计划指纹和短有效期，避免批准 A 后实际执行已经变化的 B。
