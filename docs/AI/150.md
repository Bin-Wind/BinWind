# Agent 事件重放：用不可变记录复现一次任务

只保存最终回答无法解释 Agent 为什么调用某个工具。事件重放需要按顺序记录输入、决策、工具请求、工具结果和状态转移，同时明确哪些外部事实不能再次读取。

## 设计事件信封

每条事件包含任务 ID、递增序号、类型、时间、父事件、载荷摘要和模式版本。敏感字段按策略加密或删除，工具结果保存内容哈希与必要快照，不能只留一个可能失效的 URL。

```json
{"seq":12,"type":"tool_result","parent":11,
 "tool":"inventory.read","schema":2,"payload_sha256":"…"}
```

日志采用追加写入；修正错误要追加补偿事件，不能偷偷改写历史。并行分支除顺序号外还需因果关系，否则按墙上时间排序可能得到错误重放顺序。

## 区分模拟与再次执行

诊断重放默认把历史工具结果注入 Agent，不再次触发外部副作用。若要验证真实工具，使用隔离环境、只读凭证或明确的模拟器。升级事件 Schema 时保留迁移器和旧样本回归测试，确保半年后的记录仍能被解释，而不只是“文件还在”。
