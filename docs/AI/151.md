# 模型变更冻结窗口：在高风险时期减少变量

模型、特征、提示词和运行时都可能改变线上答案。业务大促、财务结算或监管报送前设置冻结窗口，目的不是停止改进，而是让异常发生时少几个待排查变量。

## 先定义冻结范围

把变更按对象和风险登记：模型权重、分词器、特征逻辑、推理镜像、路由比例与评测阈值。文档和只读监控通常可以继续；会改变输出或容量的操作则需暂停。冻结应写明开始与结束时间、负责人、例外审批人和回滚入口。

```python
from datetime import datetime, timezone

FREEZE_START = datetime(2026, 9, 20, 0, tzinfo=timezone.utc)
FREEZE_END = datetime(2026, 9, 22, 0, tzinfo=timezone.utc)

def deployment_allowed(now: datetime, emergency: bool = False) -> bool:
    in_freeze = FREEZE_START <= now < FREEZE_END
    return not in_freeze or emergency

print(deployment_allowed(datetime.now(timezone.utc)))
```

生产门禁还应校验例外单号，而不能只相信布尔参数。紧急修复必须保留双人审批、影响说明和可执行回滚步骤。

## 结束冻结也要有顺序

冻结期间积压的变更不要同时释放。先重新基于最新基线执行回归评测，再按低风险到高风险逐项灰度；每次只引入一个主要变量并观察完整指标窗口。最后复盘冻结是否真的降低了故障定位时间，避免仪式化。
