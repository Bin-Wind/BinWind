# 推理采样留痕：不保存敏感原文也能排查问题

线上排障需要代表性请求，但直接保存完整提示词和回答会扩大隐私风险。更稳妥的做法是先明确排障问题，再只记录足够回答该问题的元数据与受控样本。

## 分层记录

常规日志保存请求 ID、模型版本、模板版本、采样参数、输入输出长度、耗时、状态码和安全策略结果。内容默认不落盘；只有进入经过审批的采样规则时，才对允许字段做脱敏和短期保存。

```python
import hashlib, json

def audit_record(request_id: str, user_id: str, prompt: str) -> str:
    return json.dumps({
        "request_id": request_id,
        "user_hash": hashlib.sha256(user_id.encode()).hexdigest()[:16],
        "prompt_chars": len(prompt),
        "prompt_hash": hashlib.sha256(prompt.encode()).hexdigest(),
    }, ensure_ascii=False)

print(audit_record("req-42", "user-7", "请总结这段文字"))
```

哈希只能帮助关联完全相同的值，不等于匿名化；低熵标识仍可能被枚举。生产中应使用带密钥的 HMAC，并把密钥与日志分开管理。

## 验收清单

采样策略应有用途、比例、保留期、访问角色和删除验证。排障结束后确认对象存储、检索索引与缓存都已过期。用合成的敏感字段跑一次测试，证明日志、指标标签和异常堆栈都不会泄露原文。
