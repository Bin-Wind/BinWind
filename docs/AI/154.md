# DPO 配对顺序审计：避免偏好标签悄悄颠倒

DPO 样本通常包含同一提示下的 `chosen` 与 `rejected` 回答。字段映射、导出脚本或人工标注界面一旦把两者交换，训练仍能正常运行，却会稳定地学向错误方向。

## 在入库前检查不变量

除了字段非空，还应检查两条回答不同、提示相同、来源可追溯，并对高置信规则建立哨兵样本。例如明确要求 JSON 的任务，可验证首选回答是否满足格式。

```python
import json

def valid_pair(row: dict) -> bool:
    if not row["prompt"].strip() or row["chosen"] == row["rejected"]:
        return False
    try:
        json.loads(row["chosen"])
        chosen_json = True
    except json.JSONDecodeError:
        chosen_json = False
    return chosen_json if row.get("expects_json") else True

sample = {"prompt": "返回 JSON", "chosen": '{"ok":true}',
          "rejected": "好的", "expects_json": True}
print(valid_pair(sample))
```

## 用盲审验证方向

从每个数据来源分层抽样，隐藏字段名并随机左右位置，让复核者重新选择。分别统计一致率和“整批反向”现象。若某来源显著异常，隔离整个批次，追溯转换链路，不要只删除被发现的几条。
