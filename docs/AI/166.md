# 微调评测集版本：让指标变化能追溯到样本

“准确率提高 2%”只有在评测集没有变化时才可直接比较。修正文案、删除泄漏样本、补充难例都会改变分母；若仍沿用同一个文件名，模型进步与题目变化就混在了一起。

## 为评测集建立身份

每个版本应包含不可变的样本文件、样本 ID、Schema、构建脚本版本和内容摘要。样本 ID 应来自稳定业务键或规范化内容哈希，不能使用每次导出都会变化的行号。另建变更日志，写明新增、删除、改标和修正文案的数量及原因。

评测结果必须同时记录模型版本、评测集版本、生成参数、评分器版本与代码提交。对生成任务，温度、最大长度、停止词和提示模板都会影响结果，不能只保存一个最终分数。

## 在版本之间建立桥梁

评测集更新时，先在新旧版本的交集样本上同时计算指标：

1. 用交集分数判断模型本身是否变化；
2. 用新增难例的单独分数理解数据集为何更难；
3. 对被删除样本保留原因，不从历史报告中抹去；
4. 按语言、任务和难度分层，防止总分掩盖局部退化。

不要为了保持曲线漂亮而长期冻结有缺陷的评测集。更稳妥的做法是让版本明确，并在仪表盘中断开不可直接比较的曲线。发布门禁可指定“必须通过 v3.2”，历史实验则继续引用各自版本。这样评测集可以持续改进，模型结论也不会因为分母悄悄变化而失真。
