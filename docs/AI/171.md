# RAG 多租户隔离：从索引分区到缓存键

在多客户知识库中，权限过滤漏一次就是数据泄露。只在生成提示词里写“不要透露其他客户信息”没有意义；隔离必须在检索之前生效，并贯穿索引、缓存、日志和评测。

## 选择明确的隔离边界

高敏感或规模较大的租户可使用独立索引与加密密钥；共享索引则必须让 `tenant_id` 成为服务端强制过滤条件，不能接受客户端传入后原样信任。写入时从认证上下文绑定租户，查询时由同一可信上下文生成过滤器。

所有派生对象也要带边界：切片 ID、向量、倒排条目、引用、反馈和删除任务都需关联租户。缓存键至少包含租户、用户权限版本、索引快照、规范化查询和检索配置；缺少租户的全局答案缓存尤其危险。

```text
cache_key = hash(
  tenant_id | permission_version | index_snapshot |
  normalized_query | retrieval_config_version
)
```

## 用负向测试证明隔离

建立两个测试租户，放入故意相似但内容不同的文档。用 A 的凭证查询 B 的独有短语，要求关键词、向量、建议问题和缓存命中全部返回空；随后改变用户权限版本，确认旧缓存不再可用。删除租户时验证原文、切片、向量、缓存和备份策略中的处理路径。

日志可以记录租户 ID 和对象 ID，但应限制原文暴露。管理员跨租户检索属于单独能力，必须显式授权和审计。真正的隔离不是某个过滤条件，而是一条从认证到最终引用都无法绕过的边界。
