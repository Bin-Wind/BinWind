# Agent Webhook 去重：外部事件重放时只处理一次

支付、工单或代码托管平台在超时后会重发 Webhook。若 Agent 每收到一次就再次发消息、创建任务或退款，同一个事件便会产生多次副作用。正确目标不是阻止重试，而是让重放得到同一个处理结果。

## 先验证，再占用幂等键

接收端先按平台规范验证签名与时间戳，再读取平台提供的稳定事件 ID。不要用请求到达时间生成键；若平台没有 ID，可由事件类型、业务对象 ID 和稳定版本字段组成键，并记录构造规则。

在数据库中用唯一约束原子插入事件记录。插入成功的 Worker 才能执行；若键已存在，则返回已接受，并根据状态决定是复用结果还是等待处理中任务。不能用“先查询再插入”，两个并发请求会同时看到不存在。

```sql
INSERT INTO webhook_events(event_id, status)
VALUES (:event_id, 'processing')
ON CONFLICT (event_id) DO NOTHING;
```

## 区分接收成功与业务成功

快速持久化事件后即可向发送方确认，耗时步骤交给队列。处理记录至少包含 `processing`、`succeeded` 和 `failed-retryable`，并保存副作用的业务键。若 Agent 在外部调用后、本地记成功前崩溃，外部操作也必须带幂等键，或在重试前查询其结果。

去重记录的保留期要覆盖上游可能的最长重放窗口。测试应包括同一事件串行重放、并发重放以及处理中崩溃恢复。幂等不是“忽略第二次请求”，而是无论送达多少次，系统都收敛到一次可证明的业务结果。
