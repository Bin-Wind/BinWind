# 机器学习流水线：把训练步骤变成可重复任务

手工依次执行清洗、特征构建、训练和评估，很容易遗漏参数或误用旧产物。流水线应把每一步的输入、输出和依赖写成机器可检查的契约。

## 一个最小流水线

下面的 Python 示例只依赖标准库，可直接运行：

```python
from pathlib import Path
import json

ROOT = Path(__file__).parent

def prepare() -> Path:
    rows = [1, 2, 3, 4, 5]
    output = ROOT / "prepared.json"
    output.write_text(json.dumps(rows), encoding="utf-8")
    return output

def train(dataset: Path) -> Path:
    rows = json.loads(dataset.read_text(encoding="utf-8"))
    model = {"mean": sum(rows) / len(rows)}
    output = ROOT / "model.json"
    output.write_text(json.dumps(model), encoding="utf-8")
    return output

def evaluate(model_path: Path) -> None:
    model = json.loads(model_path.read_text(encoding="utf-8"))
    assert 0 <= model["mean"] <= 10, "metric gate failed"
    print({"status": "passed", **model})

if __name__ == "__main__":
    evaluate(train(prepare()))
```

真实系统可由 CI、Airflow、Prefect 或云平台调度，但步骤函数仍应保持同样的清晰边界。

## 设计原则

1. **幂等**：同样输入重复执行，得到同样结果。
2. **产物明确**：每一步声明输出路径、格式和 schema。
3. **失败即停**：评估阈值不达标，不进入部署阶段。
4. **参数外置**：环境差异由配置表达，不在代码里改常量。
5. **可观察**：记录开始时间、耗时、数据版本、指标和异常。

## 缓存与重跑

缓存键应包含代码版本、输入数据哈希和参数。只用文件名作为缓存键会复用过期结果。失败重跑时从最后一个成功且输入未变的步骤继续；对写数据库或发消息等有副作用的步骤，增加幂等键，避免重复执行。

先把依赖关系做对，再选择编排平台。复杂的调度界面无法弥补含糊的输入输出。
