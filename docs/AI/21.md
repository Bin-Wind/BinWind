# AI 模型灰度发布与安全回滚

离线指标更好，不代表新模型一定适合全部线上流量。灰度发布通过小范围验证延迟、成本和业务效果，把故障影响控制在可接受范围内。

## 发布前的三道门

- **可复现门**：模型、代码、提示词、特征和依赖都有版本号。
- **质量门**：固定评测集达到阈值，关键安全用例无退化。
- **运行门**：压测覆盖目标吞吐，超时、限流和降级策略可用。

## 确定性分流

同一用户应稳定落入同一版本，避免体验抖动：

```python
import hashlib

def choose_version(user_id: str, canary_percent: int = 5) -> str:
    if not 0 <= canary_percent <= 100:
        raise ValueError("percent must be between 0 and 100")
    digest = hashlib.sha256(user_id.encode()).digest()
    bucket = int.from_bytes(digest[:4], "big") % 100
    return "candidate" if bucket < canary_percent else "stable"

assert choose_version("demo-user", 0) == "stable"
assert choose_version("demo-user", 100) == "candidate"
```

不要用 Python 内置 `hash()` 做跨进程分桶，因为其结果默认带随机化。

## 观察哪些指标

同时关注模型质量、系统健康和业务结果：任务成功率、人工纠正率、拒答率、P95 延迟、错误率、单请求 token 或 GPU 成本。比较时固定用户群与时间窗口，避免流量结构变化造成假结论。

## 回滚设计

回滚不应依赖现场重新构建。保留上一稳定模型和配置，让路由层能在分钟级切回。数据库 schema、向量索引或特征格式发生变化时，先保证新旧版本可并存；无法向后兼容的迁移要单独演练。

建议按内部流量、1%、5%、20%、50%、100% 逐级扩大，并为每级设置最低观察量而非只看时间。任何硬性安全指标越界立即自动回滚，软性业务指标则结合样本量人工判断。
