# SFT 数据质量诊断：从损失曲线找到脏样本

监督微调效果不稳定时，第一反应不应总是调学习率。格式错误、答案截断、角色错位和近重复样本，往往比超参数更直接地破坏模型行为。

## 训练前检查

下面的脚本检查 JSONL 对话数据的基本结构：

```python
import json
from pathlib import Path

VALID_ROLES = {"system", "user", "assistant"}

def validate(path: str) -> None:
    seen = set()
    for line_no, line in enumerate(Path(path).read_text().splitlines(), 1):
        row = json.loads(line)
        messages = row.get("messages", [])
        assert messages, f"line {line_no}: empty messages"
        assert messages[-1]["role"] == "assistant", f"line {line_no}: no answer"
        for message in messages:
            assert message.get("role") in VALID_ROLES, f"line {line_no}: bad role"
            assert str(message.get("content", "")).strip(), f"line {line_no}: empty content"
        fingerprint = "\n".join(m["content"].strip() for m in messages)
        assert fingerprint not in seen, f"line {line_no}: duplicate"
        seen.add(fingerprint)

validate("train.jsonl")
```

结构校验后再统计长度分布、语言比例、来源、类别占比和拒答样本比例。训练集与验证集要按来源或用户分组切分，防止同源近重复泄漏。

## 从现象反推问题

- 训练损失很低、验证任务差：可能是重复过多或答案模板化。
- 输出经常被截断：检查最大长度和超长样本处理方式。
- 模型忽略系统指令：检查训练模板是否把角色标记正确加入损失。
- 特定领域明显退化：检查采样权重，别让大类完全淹没小类。

## 小规模闭环

先用几百条高置信样本做短跑，人工审阅固定用例，再扩大数据。为每个清洗规则保留“删除数量 + 示例 + 原因”，否则质量提升无法审计，也容易误删困难但有价值的样本。
