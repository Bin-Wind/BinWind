# RAG 文档切分与元数据设计实战

切分不是把文本机械地每 500 字截断。一个好片段应能独立表达事实，同时保留足够的来源信息供检索、过滤和引用。

## 先按结构，再按长度

优先使用标题、段落、列表、代码块和表格等自然边界。只有单个结构块仍超长时，才按句子继续拆分。重叠窗口适合跨段依赖，但过大会制造重复召回并浪费上下文。

下面展示一个无第三方依赖的段落切分器：

```python
def chunk_paragraphs(text: str, max_chars: int = 400) -> list[str]:
    chunks, current = [], []
    size = 0
    for paragraph in filter(None, map(str.strip, text.split("\n\n"))):
        extra = len(paragraph) + (2 if current else 0)
        if current and size + extra > max_chars:
            chunks.append("\n\n".join(current))
            current, size = [], 0
        current.append(paragraph)
        size += extra
    if current:
        chunks.append("\n\n".join(current))
    return chunks
```

真实场景还要对超长段落做句级兜底，并保护代码块不被截断。

## 元数据最小集合

每个片段至少保存 `document_id`、`chunk_id`、标题路径、来源 URL 或文件、版本、更新时间、语言和权限标签。`chunk_id` 应由稳定文档标识与位置生成，内容更新时另存内容哈希，便于增量重建索引。

## 用问题驱动参数

操作手册适合较小片段，方便定位单一步骤；制度与合同需要携带完整条款上下文；表格可将表头复制到每个分片。准备一组真实问题，比较不同切分方案的 Recall@K、引用完整性和上下文 token 数，而不是凭视觉选择长度。

当回答缺少限定条件时，优先检查切分是否丢掉父标题或前置定义。很多“模型幻觉”，源头其实是片段失去了语境。
