# RAG 评测体系：从检索命中到答案忠实度

只抽查几个回答，无法判断 RAG 改动是否真的有效。评测应把系统拆成检索与生成两层，并用可复现的数据集持续回归。

## 评测样本结构

每条样本建议包含：问题、可接受答案要点、相关文档 ID、不可缺少的引用、难度与业务标签。问题应覆盖事实查询、多跳推理、无答案、时效边界和权限拒答。

## 检索指标

`Hit@K` 判断前 K 条中是否出现相关文档，MRR 关注第一个相关结果的位置：

```python
def reciprocal_rank(results: list[str], relevant: set[str]) -> float:
    for rank, doc_id in enumerate(results, 1):
        if doc_id in relevant:
            return 1 / rank
    return 0.0

cases = [
    (["a", "b", "c"], {"b"}),
    (["x", "y"], {"z"}),
]
print(sum(reciprocal_rank(r, g) for r, g in cases) / len(cases))
```

多相关文档任务还应计算 Recall@K，避免只命中其中一份证据。

## 生成指标

分别检查正确性、证据忠实度、引用准确性和回答完整性。“看起来合理”不等于有证据支持。模型评分可以提高覆盖率，但要用人工标注样本校准，并定期检查评分器漂移。

## 回归与诊断

每次改动保存整体分数、标签切片和失败样本。总分上升但“无答案”切片退化，仍可能不能发布。失败时按召回缺失、排序靠后、上下文冲突、生成忽略证据四类归因，对症调整。

评测集也需要版本控制。新增线上失败案例时保留来源与脱敏记录，训练集和评测集严格隔离，才能让分数持续有意义。
