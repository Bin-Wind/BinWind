# Agent 工具权限与沙箱：把误操作限制在边界内

能调用文件、数据库和外部 API 的 Agent，本质上拥有执行能力。提示词只能表达意图，真正的安全边界必须由工具层强制执行。

## 最小权限模型

为每个工具声明允许的动作、资源范围和风险等级。例如读取项目文件与删除目录不能共享一个笼统的“文件工具”。高风险动作要求更严格的参数校验、用户确认或双人审批。

下面用路径白名单演示最小边界：

```python
from pathlib import Path

ROOT = Path("./workspace").resolve()

def safe_read(relative_path: str) -> str:
    target = (ROOT / relative_path).resolve()
    if target != ROOT and ROOT not in target.parents:
        raise PermissionError("path escapes workspace")
    if not target.is_file():
        raise FileNotFoundError(target)
    return target.read_text(encoding="utf-8")
```

只检查字符串前缀会被 `../`、符号链接或相似目录名绕过；解析后的规范路径才可用于边界判断。对符号链接还应结合部署环境制定明确策略。

## 区分读取与副作用

搜索、预览通常可自动执行；发送消息、购买、发布和删除会改变外部状态，应提供操作摘要与精确目标。为写操作设置幂等键，重试时避免重复扣费或重复通知。

## 审计与测试

日志记录工具名、参数摘要、授权主体、策略结果和返回状态，但对令牌与隐私字段脱敏。测试集要包含路径穿越、提示注入、越权租户、超大输入和重放请求。

默认拒绝未知工具与未知参数。Agent 可以提出动作，授权系统决定动作是否允许，两者职责不能混在同一个模型判断里。
