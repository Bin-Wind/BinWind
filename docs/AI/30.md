# Agent 可观测性：追踪、评测与故障定位

Agent 一次请求可能经历多轮模型调用和工具调用。只记录最终答案，会让超时、循环和成本突增几乎无法定位。可观测性应还原完整执行轨迹，同时保护用户数据。

## 统一一次运行

给每次任务分配 `trace_id`，每个模型或工具步骤分配 `span_id`。事件至少包含步骤类型、开始与结束时间、输入输出大小、模型或工具版本、状态、重试次数和错误类别。

```python
from contextlib import contextmanager
from time import perf_counter

@contextmanager
def span(name: str):
    started = perf_counter()
    try:
        yield
    except Exception as exc:
        print({"span": name, "status": "error", "type": type(exc).__name__})
        raise
    finally:
        print({"span": name, "duration_ms": round((perf_counter() - started) * 1000, 2)})

with span("lookup_order"):
    result = {"status": "paid"}
```

示例可直接运行；生产环境应输出结构化日志并交给追踪系统聚合。

## 核心指标

监控任务成功率、平均步骤数、工具错误率、重复调用率、P95 延迟、单任务成本和人工接管率。为不同任务类型分别设基线，否则简单问答会掩盖复杂流程退化。

## 从轨迹到评测

离线回放固定任务，检查最终结果与过程约束：是否用了禁止工具、是否超过预算、引用是否真实、失败后是否正确停止。线上只采集必要字段，对正文做脱敏或采样，并设置保留期限。

告警必须指向可行动问题。例如“工具超时率五分钟内超过阈值”比“Agent 分数下降”更容易处置。观测的目标不是保存所有思考，而是用最少的安全信息解释系统做了什么。
