# 数据漂移监测：发现模型输入正在改变

模型上线后，即使代码和权重没有变化，输入分布也会因用户、季节或业务流程改变。漂移监测的目标不是直接宣布“模型失效”，而是尽早发现需要复核的信号。

## 建立基线

从稳定时期保存一份只含统计量的基线：数值特征记录分位数、均值和缺失率；类别特征记录频率最高的类别及其占比；文本可记录长度、语言和未知词比例。基线要注明时间窗、数据版本和过滤条件。

## 一个可运行的 PSI 示例

PSI 可比较两个离散分布。分箱必须由基线确定，不能让当前数据重新决定边界。

```python
from math import log

def psi(expected: list[float], actual: list[float]) -> float:
    if len(expected) != len(actual):
        raise ValueError("bins must match")
    eps = 1e-6
    return sum((a - e) * log((a + eps) / (e + eps))
               for e, a in zip(expected, actual))

print(round(psi([0.5, 0.3, 0.2], [0.4, 0.35, 0.25]), 4))
```

PSI 没有适用于所有业务的固定阈值，应结合历史波动、样本量和误报成本校准。

## 告警与处置

同时观察数据漂移、预测分布、真实效果和数据质量。告警后先排除埋点变化、延迟数据和抽样偏差，再按渠道、地区或模型版本切片。只有漂移持续且影响任务指标时，才进入重训或回滚流程。
