# 离线与在线特征一致性：避免训练服务两套逻辑

训练时计算正确、上线后效果骤降，常见原因是同一特征在离线批处理和在线服务中采用了不同定义。日期边界、缺失值、时区和聚合窗口尤其容易产生偏差。

## 一份定义，多处调用

把纯计算逻辑抽成共享函数，并明确输入、输出和缺失策略：

```python
from datetime import datetime, timezone

def account_age_days(created_at: datetime, now: datetime) -> int:
    if created_at.tzinfo is None or now.tzinfo is None:
        raise ValueError("timestamps must include timezone")
    seconds = (now.astimezone(timezone.utc) -
               created_at.astimezone(timezone.utc)).total_seconds()
    return max(0, int(seconds // 86_400))

assert account_age_days(
    datetime(2026, 1, 1, tzinfo=timezone.utc),
    datetime(2026, 1, 3, tzinfo=timezone.utc),
) == 2
```

在线请求和离线作业都调用同一版本的实现，不能复制后各自维护。

## 做对账而非只做单测

每天抽取一批真实实体，在相同事件截止时间下分别计算在线值与离线值，按特征统计相等率、最大误差和缺失差异。浮点特征使用明确容差；类别值要求完全相等。

## 防止时间穿越

训练样本只能使用预测时刻之前可获得的数据。聚合查询要显式带 `event_time <= prediction_time`，并区分事件时间与入库时间。发布新特征时先影子计算，对账稳定后再让模型读取。
