# RAG 查询改写与问题拆解

用户问题常含代词、省略和多个子问题，直接拿整句做一次检索容易漏掉关键证据。查询改写的目标是提升召回，同时保持用户原意不变。

## 三类处理

- 补全上下文：把“它的保修多久”改为包含当前产品名的独立问题。
- 生成检索词：保留原查询，并添加同义词或业务术语。
- 拆解问题：将比较、因果或多条件请求分成可独立取证的子问题。

```python
def build_queries(product: str, question: str) -> list[str]:
    base = question.strip()
    queries = [base]
    if "它" in base:
        queries.append(base.replace("它", product))
    return list(dict.fromkeys(queries))

print(build_queries("A 型路由器", "它的保修期是多久？"))
```

示例使用确定性规则；生产系统也可让模型提出候选，但必须保留原查询一起检索。

## 合并结果

对每个查询分别召回，再按文档 ID 去重，用重排器统一排序。限制改写数量，避免延迟和噪声线性增长。多子问题应分别保留证据，最后再综合回答。

## 评测

准备包含指代、多意图和术语别名的查询集，比较改写前后的 Recall@K、最终答案正确率与延迟。若召回提高但答案变差，应检查改写是否偏离原意或引入冲突证据。
