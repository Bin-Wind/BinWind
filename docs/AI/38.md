# RAG 引用设计：让答案可以核验

引用不是在答案末尾堆几个链接，而是让每个可核验主张都能定位到具体证据。良好的引用结构同时帮助用户判断，也便于系统发现无依据生成。

## 证据对象

检索结果应保留稳定文档 ID、标题、版本、段落或页码、原始地址和文本片段。生成模型只接收带编号的证据：

```json
{
  "evidence_id": "E3",
  "document_id": "policy-17",
  "version": "2026-08-01",
  "section": "4.2",
  "text": "……"
}
```

答案引用 `[E3]`，展示层再将其解析成标题与定位链接。不要让模型自行编造 URL。

## 生成约束

提示模型只依据提供的证据回答；证据不足时明确说不知道。每个数字、日期和规则紧跟引用。若来源冲突，展示差异与版本时间，不要擅自合并成一个结论。

## 自动检查

输出后检查引用 ID 是否存在、引用段落是否真的支持邻近主张、是否引用过期版本。可以抽取无引用句子做第二轮验证，但最终仍需通过人工样本评审校准。引用覆盖率高不代表忠实度高，关键是“证据是否支持这句话”。
