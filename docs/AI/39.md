# RAG 增量索引：文档更新后只处理变化

每次文档变化都重建整个知识库既慢又容易产生服务空窗。增量索引通过稳定身份、内容哈希和原子切换，只更新新增、修改和删除的片段。

## 生成稳定身份

文档 ID 应来自业务主键或规范化路径，片段 ID 则由文档 ID、分段规则版本和片段序号组成。内容哈希用于判断是否需要重新嵌入：

```python
import hashlib

def content_hash(text: str) -> str:
    normalized = "\n".join(line.rstrip() for line in text.strip().splitlines())
    return hashlib.sha256(normalized.encode("utf-8")).hexdigest()

print(content_hash("标题\n正文"))
```

不要用向量本身当身份；更换嵌入模型会让所有向量变化。

## 更新流程

先扫描源数据形成清单，与上次清单比较。新增和修改项写入新索引版本，删除项写墓碑或从新版本排除。全部校验通过后原子切换读别名，旧版本保留到回滚窗口结束。

## 一致性检查

对比源文档数、有效片段数、失败数和重复 ID；抽样执行固定查询，确认新内容可检索、删除内容不可检索。分段规则或嵌入模型变化属于全量迁移，应建立新索引，不能伪装成小规模增量更新。
