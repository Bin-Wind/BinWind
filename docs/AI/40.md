# Agent 工具调用的幂等设计

Agent 遇到超时后通常会重试。如果一次“创建订单”其实已经成功，而响应在网络中丢失，盲目重试就会创建两个订单。幂等键让相同意图的重复请求只产生一次副作用。

## 请求协议

调用方为一次业务意图生成稳定键，重试时沿用它，新意图才生成新键。服务端保存键、参数摘要、状态和结果：

```python
import hashlib
import json

def request_digest(payload: dict) -> str:
    raw = json.dumps(payload, sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(raw.encode()).hexdigest()

payload = {"sku": "A-17", "quantity": 2}
print(request_digest(payload))
```

同一个幂等键若收到不同参数，应拒绝而不是复用旧结果。

## 状态机

服务端先原子写入 `processing`，完成后保存 `succeeded` 与响应；失败要区分可重试和最终失败。并发到达的相同键只能有一个执行者，其余等待或读取已有结果。

## Agent 侧策略

工具描述应明确哪些调用会写入外部状态、是否支持幂等键，以及超时后如何查询状态。对不支持幂等的工具，Agent 应先查询再重试，或要求人工确认。日志中记录幂等键，但不要记录敏感参数全文。
