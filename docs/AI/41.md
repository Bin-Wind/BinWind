# Agent 人工审批点：在高风险动作前停下来

并非所有工具调用都应自动执行。付款、删除、对外发送和权限变更的错误成本高，适合在“计划已明确、动作尚未发生”的位置设置审批点。

## 风险分级

读取公开资料通常可自动执行；可恢复的内部写入可在限额内自动执行；不可逆或影响第三方的动作应要求审批。判断时同时考虑金额、数据敏感度、影响人数和可撤销性。

```python
def needs_approval(action: str, amount: float = 0) -> bool:
    irreversible = {"delete_account", "send_external", "grant_admin"}
    return action in irreversible or amount > 1000

assert needs_approval("send_external")
assert not needs_approval("save_draft")
```

规则应由业务配置并接受审计，示例阈值不代表通用标准。

## 审批卡片

向审批人展示将执行的动作、目标、关键参数、预期影响、不可逆部分和有效期限。不要只问“是否继续”。审批绑定计划摘要；参数变化后旧审批立即失效。

## 安全恢复

等待审批时持久化任务状态，但不要持有数据库锁或短期凭据。拒绝、超时和修改建议都应成为明确分支。执行后返回可核验结果与撤销入口，让审批成为完整控制链的一环。
