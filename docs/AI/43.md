# 模型注册表：让每次训练产物都有身份

模型文件若只叫 `final.pt`，上线后很难回答它用了哪批数据、哪些参数以及谁批准发布。模型注册表的核心不是存大文件，而是给每个不可变产物建立可追溯记录。

## 最小元数据

至少记录模型名、版本、文件摘要、训练代码提交、数据版本、评测结果和创建时间。模型二进制放对象存储，注册表只保存地址与摘要：

```python
from hashlib import sha256
from pathlib import Path

def file_sha256(path: str) -> str:
    digest = sha256()
    with Path(path).open("rb") as stream:
        for block in iter(lambda: stream.read(1024 * 1024), b""):
            digest.update(block)
    return digest.hexdigest()
```

版本一旦注册就不要覆盖；修正说明也应形成新修订记录。这样摘要相同才能证明下载的正是评测过的文件。

## 状态与晋级

可用 `candidate → staging → production → archived` 表达生命周期。晋级只改变别名指向，不移动或改写模型。每次晋级保存审批人、评测门槛和回滚目标；线上异常时，把 `production` 原子地指回上一版本。

注册表还应限制删除：生产版本及其直接前序不能被自动清理。定期从线上服务反查版本，确认“登记的生产模型”和“实际加载模型”一致。
