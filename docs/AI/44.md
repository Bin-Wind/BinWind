# 上线门禁：把离线评测变成可执行规则

评测报告如果只供人阅读，很容易在赶进度时被忽略。上线门禁把关键指标写成机器可判定的规则，并同时约束效果、性能与安全。

## 设计相对门槛

新模型不仅要达到绝对下限，还应与当前生产版本比较。下面的纯 Python 示例会拒绝正确率退化、延迟超标或安全失败的候选模型：

```python
def can_release(candidate: dict, baseline: dict) -> tuple[bool, list[str]]:
    failures = []
    if candidate["accuracy"] < baseline["accuracy"] - 0.01:
        failures.append("accuracy regression exceeds 1 percentage point")
    if candidate["p95_ms"] > 800:
        failures.append("p95 latency exceeds 800 ms")
    if candidate["safety_failures"] != 0:
        failures.append("safety suite has failures")
    return not failures, failures
```

阈值应来自业务容忍度，而不是为了让候选模型通过而临时调整。分群指标也要检查，否则总体提升可能掩盖某类用户明显退化。

## 保留人工判断

自动门禁适合阻止已知坏结果，无法证明模型在所有输入上安全。高风险场景还要抽查失败样本、数据泄漏和输出风格。门禁配置与评测集都纳入版本控制，审批记录关联到模型版本，才能在事后复现当时为何放行。
