# 推理成本预算：从 Token 估算到容量护栏

AI 服务的成本不能只看“每百万 Token 单价”。一次请求还会占用队列、缓存、网络与加速卡时间，长上下文尤其会放大首 Token 延迟。

## 建立请求账本

按路由记录输入 Token、输出 Token、模型版本、缓存命中和成功状态。先用简单公式得到可比较的直接成本：

```python
def request_cost(input_tokens: int, output_tokens: int,
                 input_per_million: float, output_per_million: float) -> float:
    return (
        input_tokens * input_per_million
        + output_tokens * output_per_million
    ) / 1_000_000

print(f"${request_cost(3200, 600, 1.5, 6.0):.6f}")
```

自托管模型则把加速卡、空闲余量和运维成本折算到成功请求或有效 Token，不能用满载吞吐假设全天运行。

## 分层控制

先删除重复上下文并设置合理的最大输出，再考虑更小模型、提示缓存或批处理。为每个租户设置单次上限和周期预算，接近上限时降级到摘要上下文或低成本模型；不能在生成到一半时静默截断关键答案。

成本看板应同时显示质量与延迟。若省钱方案让重试率上升，表面单次成本下降，完成一次任务的真实成本反而可能增加。
