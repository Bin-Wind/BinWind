# 微调数据的对话模板：避免训练与推理格式错位

同一组消息经过不同聊天模板，会产生不同的角色标记、分隔符和结束符。训练时一种格式、推理时另一种格式，模型可能学会错误续写或无法正常停止。

## 保留结构化消息

原始数据优先保存为角色与内容数组，不要提前拼成字符串：

```json
{
  "messages": [
    {"role": "system", "content": "回答要简洁。"},
    {"role": "user", "content": "什么是幂等？"},
    {"role": "assistant", "content": "重复执行产生相同结果的性质。"}
  ]
}
```

在预处理阶段使用目标模型随附的 tokenizer 模板统一渲染。训练样本通常不追加“等待助手回答”的提示；推理输入则需要追加，具体以模板接口为准。

## 做三项抽查

抽样解码 token，确认角色边界没有重复；确认损失掩码只覆盖需要学习的助手答案；确认结束符被包含且不会被截断。再用一条训练样本走完整推理预处理，比较前缀是否一致。

模板名称、tokenizer 版本和预处理代码提交应与数据版本一起登记。更换基础模型时重新渲染，而不是直接复用旧模型的拼接文本。
