# 序列打包与 Padding：提升微调吞吐但不串样本

短样本若全部补齐到固定长度，大量计算会浪费在 Padding 上。序列打包把多条短样本放进同一训练序列，可以提高有效 Token 比例，但边界处理不当会让模型跨样本学习。

## 先量化浪费

设批次最大长度为 2048，而样本平均只有 420 Token，独立补齐时有效率约为 20%。应先统计长度分位数，再选择最大长度和分桶策略，而不是盲目拉满上下文。

## 打包的三个边界

每条样本末尾要有正确结束符；标签掩码必须保留各自规则；注意力矩阵应阻止后一个样本读取前一个无关样本（若训练框架不支持隔离注意力，就要明确接受这种影响或不用打包）。

可先用贪心方式验证装箱逻辑：

```python
def pack(lengths: list[int], limit: int) -> list[list[int]]:
    batches: list[list[int]] = []
    for length in sorted(lengths, reverse=True):
        if length > limit:
            continue
        target = next((b for b in batches if sum(b) + length <= limit), None)
        if target is None:
            batches.append([length])
        else:
            target.append(length)
    return batches
```

这段代码只用于估算利用率，真实训练仍应使用框架实现。记录“有效训练 Token / 总计算 Token”，并比较开启打包前后的验证集结果，吞吐提升不能替代质量检查。
