# Agent 工具 Schema 设计：让参数可验证也可理解

工具说明既是模型的接口文档，也是运行时校验契约。字段含糊、可选项过多或单位不明，会让 Agent 即使选对工具也传错参数。

## 收紧输入边界

名称表达业务含义，描述写清单位、格式和副作用。能用枚举就不用自由文本，能由服务端推导的身份信息不要交给模型填写：

```json
{
  "type": "object",
  "properties": {
    "order_id": {"type": "string", "minLength": 1},
    "action": {"type": "string", "enum": ["cancel"]},
    "reason": {"type": "string", "maxLength": 200}
  },
  "required": ["order_id", "action"],
  "additionalProperties": false
}
```

运行时仍需鉴权和业务校验；Schema 通过不代表调用被授权。

## 返回稳定结果

返回值区分成功、可重试错误和最终错误，并提供机器可读错误码。避免把所有信息塞进自然语言。写操作返回资源编号和最终状态，便于 Agent 查询，而不是因超时盲目重试。

用真实对话建立契约测试：缺字段、错单位、额外字段、资源不存在和权限不足都应有确定结果。修改 Schema 时做版本迁移，避免正在运行的长任务突然失去兼容性。
