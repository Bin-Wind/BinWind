# Agent 计划与执行分离：让长任务更容易校正

复杂任务若边想边产生外部副作用，一旦理解偏差就很难收回。把计划与执行分开，可以在真正写入前检查范围、依赖和风险。

## 计划是可检查的数据

每一步包含目标、输入、工具、预期输出和是否有副作用：

```python
plan = [
    {"id": "inspect", "tool": "list_files", "writes": False, "depends_on": []},
    {"id": "edit", "tool": "update_doc", "writes": True, "depends_on": ["inspect"]},
    {"id": "verify", "tool": "build_docs", "writes": False, "depends_on": ["edit"]},
]

assert all(step["id"] not in step["depends_on"] for step in plan)
```

执行器只运行依赖已完成的步骤，并在高风险写入前校验授权。计划不是不可变剧本；观察结果与假设冲突时，应停止、修订后再继续。

## 防止计划表演化

不要要求模型写几十步漂亮计划。计划粒度以能验证和恢复为准，每步产出应可判定。执行记录保存工具参数摘要、结果和状态，失败后从最近的安全检查点继续。

对只读小任务不必强行拆层；计划与执行分离主要服务于长链路、昂贵调用和不可逆操作。
