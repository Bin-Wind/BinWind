# 训练数据血缘：从样本追踪到模型版本

模型指标异常时，最重要的问题不是“谁改了代码”，而是“这个模型究竟看过哪些数据”。数据血缘应把原始来源、清洗规则、快照版本、训练任务和模型产物串成可查询链路。

## 为快照建立不可变身份

不要用“最新版”作为训练输入。导出数据后生成清单，记录相对路径、字节数与 SHA-256；训练任务只引用清单摘要：

```python
import hashlib
from pathlib import Path

def manifest(root: Path) -> list[tuple[str, int, str]]:
    rows = []
    for path in sorted(p for p in root.rglob("*") if p.is_file()):
        digest = hashlib.sha256(path.read_bytes()).hexdigest()
        rows.append((str(path.relative_to(root)), path.stat().st_size, digest))
    return rows
```

大文件应流式计算摘要。清单本身也要进入对象存储或版本库，并设置只读保留策略；哈希能发现变化，却不能代替访问控制。

## 记录转换与去向

每个派生数据集保存父快照 ID、转换代码提交、参数、运行环境和质量报告。模型注册记录再引用训练快照、验证快照与训练任务 ID。这样发现某来源授权撤回或某清洗规则有误时，才能反查受影响模型。

血缘链还要验证“能否重建”：定期抽取一个历史模型，在隔离环境重跑清单校验和关键转换。只保存元数据却丢失原始快照，并不是真正可恢复的血缘。
