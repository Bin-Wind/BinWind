# 模型服务 SLO：同时约束延迟、可用性与质量

只监控 HTTP 200 会掩盖“服务在线但答案不可用”。模型服务的目标至少包含可用性、尾延迟、质量和成本四个维度，并明确统计窗口与适用流量。

## 定义用户可感知指标

流式生成可分别记录首 Token 时间和完整响应时间；非流式接口关注整体 P95/P99。可用性应排除调用方的非法请求，但包含超时、容量拒绝和内部降级失败。质量指标可用经过人工校准的自动评测加稳定抽样审核。

- 28 天窗口内成功率不低于 99.9%；
- 正常长度请求的首 Token P95 小于 1.5 秒；
- 固定回归集的关键任务通过率不低于发布基线；
- 单次成功请求的平均成本不超过预算。

## 用错误预算驱动取舍

把允许失败量转换成错误预算。预算消耗过快时暂停高风险发布，优先做容量和可靠性修复；质量下降也应消耗自己的预算，不能因接口成功而忽略。

仪表盘按模型、区域、请求长度和租户分层，避免平均值隐藏长上下文故障。告警使用多窗口燃烧率，既捕获突发事故，也发现缓慢恶化。每次目标调整都记录用户影响和成本依据，SLO 才不会变成随意移动的数字。
