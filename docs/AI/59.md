# 可训练参数审计：确认微调真的只改了该改的层

LoRA 或冻结式微调最隐蔽的错误，是配置没有命中目标层，或意外解冻了整个骨干模型。训练能正常运行，并不表示可训练参数符合预期。

## 训练前生成清单

在创建优化器之前遍历参数，输出名称、形状与是否可训练，并计算比例：

```python
def trainable_report(model) -> tuple[int, int]:
    trainable = 0
    total = 0
    for name, parameter in model.named_parameters():
        count = parameter.numel()
        total += count
        if parameter.requires_grad:
            trainable += count
            print(f"{name:60} {tuple(parameter.shape)}")
    print(f"trainable={trainable:,} total={total:,} ratio={trainable / total:.4%}")
    return trainable, total
```

为预期目标模块写断言，例如至少命中一个注意力投影层，且可训练比例落在批准范围。名称规则应针对实际模型检查，不能从另一架构复制。

## 用一步更新验证边界

跑一个最小批次后，对训练前后的参数摘要做比较：目标层必须变化，冻结层必须不变。还要确认优化器只接收可训练参数，否则会浪费状态内存。

将清单、适配器配置和断言结果保存为训练产物。恢复训练时重新审计，因为模型版本变化可能让模块名称失效。一次几十毫秒的检查，常能避免数小时无效训练或错误发布。
