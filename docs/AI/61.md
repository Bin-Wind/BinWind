# RAG 检索去重与多样性：避免上下文被同一文档占满

相邻切片通常语义高度相似。若只取相似度最高的若干段，结果可能全部来自同一页，模型看到的是重复证据而非完整视角。

## 先合并重复，再平衡来源

索引阶段为每个切片保存文档 ID、章节 ID 和字符范围。召回后先按内容指纹去掉完全重复项，再合并同一章节中重叠的相邻范围。最后设置每个文档或章节的候选上限。

可以用最大边际相关性在“贴近问题”和“彼此不同”之间取舍：

```python
def mmr_score(query_similarity: float, max_selected_similarity: float,
              relevance_weight: float = 0.7) -> float:
    return (
        relevance_weight * query_similarity
        - (1 - relevance_weight) * max_selected_similarity
    )
```

首条候选没有已选相似度时按 0 处理。多样性不是随机打散；合同编号、权限范围等精确问题仍应优先保留最直接证据。

## 用覆盖率评测

评测集标注答案需要哪些证据点，比较去重前后的重复 Token 比例、证据覆盖率和最终答案正确率。若多样性提升却引入无关材料，应调高相关性权重或先做最低分过滤。

日志保留最终入模片段及淘汰原因，才能解释某条证据为何消失。上下文槽位有限，去重的目标是让每个 Token 提供新的有效信息。
