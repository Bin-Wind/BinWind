# Agent 状态机：让长任务的转移条件清晰可查

仅靠自然语言计划驱动长任务，容易重复执行、跳过审批或在失败后不知道从哪里恢复。显式状态机把允许的阶段和转移条件写进执行器。

## 状态与事件分离

状态描述任务现在处于哪里，事件描述发生了什么。转移表只允许已审核路径：

```python
TRANSITIONS = {
    ("draft", "validated"): "ready",
    ("ready", "approved"): "executing",
    ("executing", "succeeded"): "verifying",
    ("executing", "failed"): "recovering",
    ("verifying", "accepted"): "done",
}

def transition(state: str, event: str) -> str:
    try:
        return TRANSITIONS[(state, event)]
    except KeyError as error:
        raise ValueError(f"不允许的转移: {state} + {event}") from error
```

高风险操作必须从 `ready` 经审批事件进入执行态，模型文字不能直接把状态改成完成。

## 保存可恢复快照

每次转移以追加事件写入持久存储，包含任务 ID、前后状态、事件、时间和幂等键。恢复时重放事件并核对外部副作用，不能看到进程崩溃就盲目重做。

为超时、取消和人工驳回设计终态，并明确哪些状态可补偿。测试覆盖所有允许转移与非法转移。状态机不会替 Agent 做决定，但能保证决定只沿着可解释、可审计的路径执行。
