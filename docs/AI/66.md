# Agent 密钥管理：最小暴露、短期凭证与日志脱敏

Agent 会组合多种工具，若把长期密钥直接放进上下文，一次提示注入或调试日志就可能泄露所有权限。密钥应由执行环境持有，模型只获得调用能力。

## 用代理隔离凭证

工具代理根据任务身份检查允许的服务、动作和资源范围，再在服务端注入凭证。优先使用短期令牌，并限制受众、权限与有效期。生产、测试和个人环境必须分开。

应用读取环境变量时要立即检查，但不要输出值：

```python
import os

def required_secret(name: str) -> str:
    value = os.environ.get(name)
    if not value:
        raise RuntimeError(f"缺少必要配置: {name}")
    return value
```

环境变量比写进源码好，但仍可能被子进程或诊断信息读取；高要求场景应使用密钥管理服务和按需获取。

## 默认不进入日志

请求头、连接串、签名参数和工具原始响应都应先经过字段级脱敏。不要只替换固定前缀，未知格式的令牌仍会漏出。错误页面和截图同样可能含密钥。

建立轮换与撤销演练：确认旧凭证失效、依赖服务平滑切换、审计能定位使用者。怀疑泄露时先撤销再调查，不能等待确认后才行动。
