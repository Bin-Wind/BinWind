# 模型事故响应：从止损到可复现复盘

模型事故可能表现为质量骤降、延迟飙升、越权输出或成本异常。第一目标是限制影响面，而不是立刻猜根因。预先定义值班人、升级条件、回滚权限和用户通知模板。

## 保存证据后再切换版本

记录事件开始时间、模型与提示词版本、流量比例、依赖状态和脱敏请求样本。若安全或合规风险仍在扩大，立即停用相关能力；普通质量故障可切回已验证版本或关闭新路由。回滚后仍要确认指标恢复，不能把部署成功当成事故结束。

排查时逐层比较输入分布、检索结果、模型响应、后处理和外部工具。用固定请求重放，但禁止把敏感生产数据复制到不受控环境。

复盘应写清时间线、用户影响、触发条件、为何监控没有更早发现，以及每个改进项的负责人和截止时间。把事故样本加入回归集，同时增加能提前发现同类问题的门禁；只写“加强测试”不是可执行的改进。
