# 向量模型迁移：双索引验证后再切流量

更换嵌入模型会改变向量维度和空间含义，旧向量不能与新查询向量混用。直接覆盖索引既难回滚，也无法判断召回变化来自模型还是数据。

## 建立可并行读取的新版本

为索引记录嵌入模型标识、维度、归一化方式、切分版本和生成时间。后台重建新索引时，文档更新同时写入新旧版本，或记录变更日志供追赶。只有当新索引追平水位后才开始影子查询。

用真实问题集合比较 Recall@k、首个相关结果位置、延迟和无结果率，并按语言、文档类型与问题难度分层。向量模型变化可能要求重新调整相似度阈值和重排器，不能沿用旧阈值。

先让少量可观测流量读取新索引，持续保留旧索引和切换开关。确认质量、成本和延迟稳定后停止双写，最后按保留策略删除旧索引。迁移完成条件应包含“可回滚窗口结束”，而不只是“向量生成完毕”。
