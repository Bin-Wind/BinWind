# RAG 缓存失效：内容更新后不再返回旧答案

RAG 可以缓存查询改写、检索结果或最终答案，但不同层的失效条件不同。只按问题文本设置长 TTL，会在政策、库存或权限变化后继续返回过期内容。

## 把版本写进缓存键

检索缓存键至少包含规范化查询、索引版本、过滤条件和租户；答案缓存还应包含提示词、模型、引用文档版本与权限摘要。文档更新时发布版本事件，主动删除关联答案，TTL 只作为兜底。

```python
import hashlib, json

def cache_key(query: str, index_version: str, tenant: str) -> str:
    payload = {"q": " ".join(query.split()), "index": index_version, "tenant": tenant}
    raw = json.dumps(payload, sort_keys=True, ensure_ascii=False)
    return hashlib.sha256(raw.encode()).hexdigest()
```

不要跨用户缓存含个性化或受限内容的最终答案。记录命中层级、生成版本和失效原因，才能判断缓存是否真的节省成本。上线前测试文档删除、权限收回、索引切换和模型升级，确认旧缓存不会穿透新的边界。
