# 影子流量验证：新模型先观察再接管答案

离线分数无法覆盖真实请求分布。影子流量把生产请求的脱敏副本发送给候选模型，但候选结果不返回用户，用于比较延迟、成本与质量风险。

## 隔离副作用与资源

影子请求必须带独立标记，禁止触发写数据库、发消息等工具调用；必要时只回放纯推理部分。为候选服务设置单独并发上限，避免影子负载挤占生产容量。敏感字段应在复制前删除或令牌化，并遵守数据保留规则。

比较时按语言、输入长度、业务场景和高风险请求分层，而不是只看总平均。记录两套模型的输出摘要、首 Token 延迟、总耗时、Token 数和错误类型。自动评分适合筛查，最终切换仍需抽样人工复核。

先从极小比例开始，确认资源与日志正确后逐步增加。影子验证通过只说明“值得试运行”；真正接管流量还需要灰度、回退条件和线上用户指标。
