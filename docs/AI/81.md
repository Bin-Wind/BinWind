# 特征回填任务：在大规模重算中保证幂等

特征逻辑升级后，历史样本常要重新计算。回填任务耗时长、容易中断，还可能与在线写入并行，因此必须从一开始设计分片、幂等和校验。

## 用版本化写入避免覆盖

不要原地改旧列。为新特征写入 feature_version，主键使用“实体、事件时间、版本”的组合；同一分片重复执行应得到相同结果。按时间窗或稳定哈希分片，并为每片记录输入范围、代码版本、状态、行数与校验和。

回填先跑一个小时间窗，比较空值率、分位数、类别分布和与旧特征的差异。大批量运行时限制读取速率，避免拖慢线上数据库；失败只重跑未完成分片，不从头开始。

切换读取版本前，验证训练与在线服务都认识新 schema，并预留双读比较期。确认覆盖率和一致性后再停止旧版本写入；旧数据的清理应是独立、可审计的后续任务。
