# 微调样本长度分布：别让少数长文本吞掉预算

样本条数不能代表训练成本。自回归训练的显存与计算主要受 Token 长度影响，少数超长对话可能拖慢整个批次，也更容易在截断后丢失关键答案。

## 先统计再决定上限

使用实际 tokenizer 统计 P50、P90、P95、P99 和最大长度，并分别观察输入与监督答案。按任务、语言和数据来源分层，避免总体分布掩盖某一类异常长样本。

长度上限应结合业务请求、显存和吞吐确定。对超长样本先判断能否安全切分；多轮对话必须保留角色边界，工具调用要成对保留。简单从尾部截断可能留下问题却删掉答案，造成错误监督。

采用长度分桶或动态批处理可减少 padding，但需要确认每个有效 token 的损失权重一致。训练报告记录 tokenizer 版本、截断策略、被截断比例和丢弃数量；更换 tokenizer 后必须重新统计，不能沿用旧阈值。
