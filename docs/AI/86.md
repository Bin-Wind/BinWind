# RAG 重排批处理：在质量提升与尾延迟间取平衡

交叉编码器重排能同时阅读查询和候选片段，通常比单纯向量排序更精确，但候选越多，计算与尾延迟越高。上线前要同时决定召回数量、批大小和超时策略。

## 先缩小候选再成批评分

向量或关键词阶段先取得适量候选，按文档去重后再送入重排器。批次按 Token 总量而不是仅按条数控制，避免一条长文把显存推到上限。对请求设置截止时间；重排超时可退回首阶段排名，但必须记录降级事件。

评测 NDCG、前 K 证据命中率的同时，记录 P95/P99 延迟、显存峰值和单位查询成本。增加候选数带来的质量收益常会递减，应选择拐点而非最大值。

批处理队列要设置最大等待时间，低流量时不能为了凑满批次而延迟请求。模型更新后用同一查询集回归，并检查长文本、中文混排和重复片段等边界情况。
