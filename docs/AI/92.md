# 推理队列背压：在过载时保护延迟与可用性

当到达速率持续高于推理吞吐时，无界队列只会把故障伪装成等待：内存增加、请求超时，而 GPU 仍在处理已经无人需要的任务。服务入口应设置队列上限和请求截止时间。

每个请求携带绝对 deadline；入队前估算剩余时间，不足以完成时立即拒绝。出队后再次检查，过期任务不再占用批次。队列满时返回明确的可重试状态，并让客户端采用有限、带抖动的退避；不要在服务端无限重排。

动态批处理要同时约束最大批量与最长等待。流量低时快速发车，流量高时再凑批，避免为了吞吐牺牲所有交互延迟。分别记录排队时间、执行时间、丢弃原因和批量大小，告警以高分位延迟和过载拒绝率为主。

背压不是扩容替代品。用压测找到稳定吞吐后设置容量水位，并预留模型加载、长输入和下游波动的余量；只有这样，过载时的拒绝才是可控降级，而不是随机崩溃。
