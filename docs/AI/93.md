# 模型回滚演练：确认旧版本仍能接住真实流量

保留旧权重不等于能够回滚。特征结构、Tokenizer、运行时镜像和下游接口可能已经变化，真正的回滚单位应是一个经过验证的发布包。

发布清单至少固定模型摘要、预处理代码、依赖镜像、配置 schema 和兼容的数据版本。演练时从当前版本切到上一稳定版本，发送包含长短输入、边界字符和典型业务的探针，再确认延迟、错误率与质量门禁。完成后切回并核对两次切换没有遗留混合实例。

数据库或索引发生不可逆迁移时，需要先设计双读、双写或向后兼容窗口；否则应用回滚会被数据层锁死。缓存键应包含模型与提示模板版本，避免旧模型读取新版本结果。

记录回滚负责人、触发条件、预计耗时和停止规则，每季度在非高峰环境演练。一次成功演练的证据是时间线、探针结果和监控截图，而不是“按钮还在”。
