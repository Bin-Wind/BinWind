# RAG 查询路由：不同问题走不同检索策略

事实查询、文档定位、汇总和闲聊不需要相同检索链。把所有请求都送进昂贵重排器，会增加延迟；完全不区分又容易给导航题返回一堆语义相似片段。

先定义少量可观察路由，例如精确标识符检索、混合语义检索、多文档汇总和无需知识库。规则可利用明确格式与词典，分类器只处理模糊情况，并输出置信度。低置信度走稳妥的混合检索，不要直接跳过证据。

用标注查询集分别评估路由准确率和端到端答案质量。错误成本不对称：把需检索问题误判为闲聊通常比多做一次检索更危险。日志记录选择的路由、候选数量、耗时和最终是否引用，但要清理敏感查询。

每条路由保留统一的权限过滤与拒答策略。优化延迟不能绕过访问控制；路由规则变化后也必须重跑越权与无答案测试。
