# 应用数据目录迁移：先识别数据库、附件与缓存

应用占用空间大时，直接把整个数据目录拖到外置盘并做软链接，可能破坏权限、锁文件和更新流程。迁移前要分清不可再生数据、可重新下载附件和可丢弃缓存。

## 先获得官方路径

优先使用应用内的存储位置设置、导出或备份功能。查阅当前版本说明，确认目标文件系统、网络盘和加密卷是否受支持。完全退出应用后再备份；仅关闭窗口可能仍有后台进程写数据库。

对原目录生成文件数、总大小和代表性摘要，复制到目标后复核。数据库及其 WAL、日志或附件索引必须作为一致整体迁移，不能在应用运行时逐个复制。保留原目录为只读回退副本，确认新位置稳定后再按保留计划清理。

## 验收真实工作流

重新启动后测试搜索、打开旧附件、新建记录、同步、离线访问和升级。断开外置盘时，应用应明确失败而不是悄悄在默认位置创建第二个库。检查备份任务是否跟随新路径，权限是否只授予需要的账户。

缓存通常无需迁移，重新生成反而更安全。任何软链接方案都应作为最后选择，并记录应用升级后需要复测的项目。
