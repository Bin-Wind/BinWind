# 应用缓存清理：先区分可重建数据与唯一副本

“清理缓存”常被当成通用修复，但一些应用把离线下载、未同步草稿甚至登录状态也放在相近目录。删除前必须知道每类数据能否重建。

## 从应用内入口开始

优先使用应用提供的存储管理页，它通常能区分缩略图、下载内容、附件和数据库。记录账号、同步状态和当前占用，先清理可重新下载的项目，再观察问题是否消失。系统设置中的“清除数据”往往比“清除缓存”范围更大，不要混用。

## 做可逆验证

退出应用并保存重要草稿；能备份时先备份。桌面应用若需人工定位目录，先移动单个已确认的缓存子目录到临时位置，而不是删除整个配置目录。重新启动后检查登录、设置、离线文件和同步队列。

若问题未解决，把缓存恢复并继续查看日志、扩展和版本兼容性。清理只是诊断实验，不应成为定期脚本；缓存会重建，频繁删除反而增加流量和启动时间。
