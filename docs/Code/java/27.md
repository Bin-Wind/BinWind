# Java 虚拟线程：高并发阻塞任务实战

虚拟线程让“一个请求一个线程”的同步写法能承载更多等待型任务。它适合网络和数据库 I/O，不会加速 CPU 密集计算，也不能突破下游连接池容量。

## 最小示例

以下代码需要 Java 21：

```java
import java.time.Duration;
import java.util.concurrent.Executors;

public class VirtualThreadDemo {
    public static void main(String[] args) throws Exception {
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            var futures = java.util.stream.IntStream.range(0, 100)
                .mapToObj(i -> executor.submit(() -> {
                    Thread.sleep(Duration.ofMillis(20));
                    return i * i;
                }))
                .toList();

            long sum = 0;
            for (var future : futures) sum += future.get();
            System.out.println(sum);
        }
    }
}
```

`try` 结束时执行器会等待已提交任务完成并关闭。

## 不要建立虚拟线程池

虚拟线程本身很轻量，通常每个任务新建一个即可。真正需要限制的是数据库连接、外部 API 配额等稀缺资源，可用 `Semaphore` 或连接池施加背压。

## 迁移检查

- 搜索长时间持有 `synchronized` 锁并执行阻塞 I/O 的代码。
- 为外部调用设置明确超时，避免廉价线程无限堆积。
- 通过线程转储和指标验证吞吐、延迟及下游压力。
- `ThreadLocal` 数据会按虚拟线程复制语义使用，不要存放昂贵对象。

虚拟线程最大的价值是保留容易阅读的同步控制流。若现有异步框架已稳定，不必只为追逐新技术重写；应以压测和维护成本决定迁移。
