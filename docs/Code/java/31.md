# Java 原子计数器：AtomicLong 与 LongAdder 怎么选

多个线程执行 `count++` 会发生丢失更新，因为读取、加一和写回不是原子操作。精确读取频繁时可用 `AtomicLong`，高并发统计更适合 `LongAdder`。

```java
import java.util.concurrent.atomic.AtomicLong;
import java.util.stream.IntStream;

public class AtomicCounter {
    public static void main(String[] args) {
        AtomicLong count = new AtomicLong();
        IntStream.range(0, 100_000).parallel()
                .forEach(ignored -> count.incrementAndGet());
        System.out.println(count.get());
    }
}
```

`AtomicLong` 的复合更新应使用 `updateAndGet`、`accumulateAndGet` 或比较并交换，不能先 `get()` 再 `set()`。

```java
import java.util.concurrent.atomic.LongAdder;

LongAdder requests = new LongAdder();
requests.increment();
long snapshot = requests.sum();
```

`LongAdder` 通过分散竞争提高吞吐，但 `sum()` 是统计快照，不适合要求线性一致的序号、余额或限额。监控计数通常可接受，业务状态则应选择更强的一致性机制。
