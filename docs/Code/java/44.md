# Java Semaphore：限制昂贵操作的并发数

线程池限制的是执行线程数量，却不一定能单独限制某个下游资源。Semaphore 可为数据库导出、第三方接口等昂贵步骤设置独立并发上限。

~~~java
import java.util.concurrent.Semaphore;

public class Main {
    private static final Semaphore LIMIT = new Semaphore(2);

    static void runTask(int id) throws InterruptedException {
        LIMIT.acquire();
        try {
            System.out.println("running " + id);
            Thread.sleep(50);
        } finally {
            LIMIT.release();
        }
    }

    public static void main(String[] args) throws Exception {
        Thread a = new Thread(() -> call(1));
        Thread b = new Thread(() -> call(2));
        a.start(); b.start(); a.join(); b.join();
    }

    private static void call(int id) {
        try { runTask(id); }
        catch (InterruptedException e) { Thread.currentThread().interrupt(); }
    }
}
~~~

只有成功 acquire 后才能 release，因此获取动作应放在 try 之前。服务请求更适合 tryAcquire 配合有限等待，超时后返回过载，而不是无限堆积线程。公平模式能减少长期饥饿，但吞吐可能下降，应按场景测量。
