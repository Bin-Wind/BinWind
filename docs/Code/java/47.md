# Java Path.resolve：把用户路径限制在根目录内

字符串前缀不能阻止 `../` 或符号链接逃出允许目录。读取已存在文件时，应将根目录与候选路径都解析为真实路径，再比较路径边界。

~~~java
import java.nio.file.Files;
import java.nio.file.Path;

public class SafeRead {
    static Path resolveExisting(Path base, String input) throws Exception {
        Path realBase = base.toRealPath();
        Path candidate = realBase.resolve(input).toRealPath();
        if (!candidate.startsWith(realBase) || !Files.isRegularFile(candidate)) {
            throw new SecurityException("path is outside the allowed directory");
        }
        return candidate;
    }

    public static void main(String[] args) throws Exception {
        Path file = resolveExisting(Path.of("."), "README.md");
        System.out.println(file);
    }
}
~~~

`normalize()` 只能消除语法上的 `..`，不能识别符号链接，所以已有文件要使用 `toRealPath()`。比较必须用 `Path.startsWith`，不能比较字符串 `/data/user` 与 `/data/user-old`。

创建新文件更复杂，因为目标还没有真实路径且存在检查后替换的竞态。高风险写入应使用操作系统隔离、不可被用户修改的父目录，或支持时通过 `SecureDirectoryStream` 相对操作，不能把读取示例直接当成安全写入方案。
