# Java Collectors.toMap：显式处理重复键

把列表收集为 Map 时，键可能重复。`Collectors.toMap` 不提供合并函数时会抛出异常；这通常比悄悄覆盖好，但业务必须明确重复项应该拒绝还是合并。

~~~java
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

public class IndexUsers {
    record User(String email, long updatedAt) {}

    public static void main(String[] args) {
        var users = List.of(
            new User("a@example.com", 10),
            new User("a@example.com", 12),
            new User("b@example.com", 9)
        );

        Map<String, User> latest = users.stream().collect(Collectors.toMap(
            user -> user.email().toLowerCase(),
            user -> user,
            (left, right) -> left.updatedAt() >= right.updatedAt() ? left : right
        ));
        latest.forEach((key, value) -> System.out.println(key + " -> " + value));
    }
}
~~~

合并函数要满足确定性。若时间相同还需第二个稳定排序条件，否则并行流或输入顺序变化会改变结果。重复本应属于数据错误时，不要为了让程序通过而写 `(a, b) -> b`，应先分组并报告冲突。

需要保留插入顺序时使用带 Map 工厂的重载并提供 `LinkedHashMap::new`。最终 Map 是否可变也要在接口边界说明，必要时再用 `Map.copyOf` 创建快照。
