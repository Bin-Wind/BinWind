# Java ReentrantLock.tryLock：为锁等待设置期限

`synchronized` 简单可靠，但无法直接限制等待时间。需要在繁忙时快速失败或降级时，可使用 `ReentrantLock.tryLock(timeout, unit)`。关键是只在确实获得锁后释放。

```java
import java.time.Duration;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.locks.ReentrantLock;

public class Inventory {
    private final ReentrantLock lock = new ReentrantLock();
    private int stock = 10;

    public boolean reserve(int amount, Duration timeout)
            throws InterruptedException {
        boolean acquired = lock.tryLock(timeout.toMillis(), TimeUnit.MILLISECONDS);
        if (!acquired) return false;
        try {
            if (amount <= 0 || stock < amount) return false;
            stock -= amount;
            return true;
        } finally {
            lock.unlock();
        }
    }
}
```

`tryLock` 会响应中断，因此方法应传播 `InterruptedException`，或恢复中断标记后按业务规则退出。不要捕获后静默重试，否则上层无法取消任务。

## 缩短临界区

锁内只做读取共享状态、验证和更新。网络请求、磁盘 IO 与耗时计算放在锁外，否则一个慢依赖会阻塞所有竞争者。如果必须先查外部信息，获得锁后要重新检查共享状态，防止查到的前提已经过期。

`new ReentrantLock(true)` 可启用公平策略，但会影响吞吐，也不保证业务层绝对公平。先用等待时间、超时率和持锁时长判断是否真的存在饥饿。
