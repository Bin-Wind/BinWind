# Java BigDecimal 比较：数值相等与表示相等不是一回事

`BigDecimal.equals` 同时比较数值和 scale，因此 `1.0` 与 `1.00` 的 `equals` 结果是 `false`；`compareTo` 只比较数值，结果为 0。金额规则必须先说明需要哪一种相等。

```java
import java.math.BigDecimal;

public class PriceCheck {
    public static void main(String[] args) {
        BigDecimal a = new BigDecimal("1.0");
        BigDecimal b = new BigDecimal("1.00");

        System.out.println(a.equals(b));         // false
        System.out.println(a.compareTo(b) == 0); // true
    }
}
```

## 从字符串构造

不要用 `new BigDecimal(0.1)` 接收十进制常量，因为二进制浮点近似值会被带进对象。使用字符串，或在确有 double 输入时使用 `BigDecimal.valueOf` 并理解其转换语义。

## 统一业务尺度

货币字段通常应在边界统一币种、scale 和舍入规则：

```java
BigDecimal normalized = amount.setScale(2, java.math.RoundingMode.HALF_EVEN);
```

不能整除的运算要显式提供 scale 和 `RoundingMode`，否则可能抛出 `ArithmeticException`。若 `BigDecimal` 作为 `HashMap` 键，`equals` 与 `hashCode` 的 scale 敏感性尤其重要；先规范化，再存入集合。
