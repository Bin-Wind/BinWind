# Java ObjectInputFilter：为反序列化设置类型与规模边界

Java 原生反序列化会按输入中的类型图创建对象。对不可信数据使用 `ObjectInputStream` 可能触发意外类、超深对象图或资源耗尽。能改协议时优先使用带显式 Schema 的格式；必须兼容旧数据时至少配置过滤器。

```java
import java.io.*;

public class SafeRead {
    public static Object read(InputStream input) throws Exception {
        try (ObjectInputStream stream = new ObjectInputStream(input)) {
            ObjectInputFilter filter = ObjectInputFilter.Config.createFilter(
                "maxdepth=10;maxrefs=1000;maxbytes=1048576;java.base/*;!*"
            );
            stream.setObjectInputFilter(filter);
            return stream.readObject();
        }
    }
}
```

规则从左到右匹配，示例限制深度、引用数和字节数，只允许 `java.base` 中的类型，最后拒绝其余类型。真实业务若需要自定义 DTO，应逐个允许明确包或类，并用测试确认数组与嵌套集合也符合预期。

过滤器不是数据真实性校验。序列化内容仍需来自经过认证与完整性保护的渠道，并在反序列化后执行字段范围验证。捕获拒绝异常时记录安全的事件摘要，不把原始载荷或敏感字段写入日志。
