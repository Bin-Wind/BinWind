# Java WatchService：监听目录并正确处理事件溢出

`WatchService` 适合触发“重新扫描”，不应被当成永不丢事件的审计日志。事件产生太快时会出现 `OVERFLOW`，应用必须退回完整对账。

```java
import java.nio.file.*;

public class WatchDemo {
    public static void main(String[] args) throws Exception {
        Path dir = Path.of(".").toAbsolutePath().normalize();
        try (WatchService watcher = FileSystems.getDefault().newWatchService()) {
            dir.register(watcher, StandardWatchEventKinds.ENTRY_CREATE,
                    StandardWatchEventKinds.ENTRY_MODIFY,
                    StandardWatchEventKinds.ENTRY_DELETE);
            WatchKey key = watcher.take();
            for (WatchEvent<?> event : key.pollEvents()) {
                if (event.kind() == StandardWatchEventKinds.OVERFLOW) {
                    System.out.println("事件溢出：需要完整扫描 " + dir);
                } else {
                    Path changed = dir.resolve((Path) event.context()).normalize();
                    System.out.println(event.kind().name() + " " + changed);
                }
            }
            if (!key.reset()) System.out.println("目录已不可访问");
        }
    }
}
```

真实服务应循环 `take()`，合并短时间内的重复事件，并在处理前重新读取当前状态，因为创建事件到达时文件可能仍在写入。不同文件系统的递归和事件语义也可能不同。
