# Java ScheduledExecutorService：区分固定频率与固定延迟

周期任务不只有“每隔五秒”一种语义。`scheduleAtFixedRate` 以计划开始时间为基准，适合采样节拍；`scheduleWithFixedDelay` 则在上一次任务结束后再等待，适合轮询外部资源。

```java
import java.time.Instant;
import java.util.concurrent.Executors;
import java.util.concurrent.ScheduledExecutorService;
import java.util.concurrent.TimeUnit;

public class SchedulerDemo {
    public static void main(String[] args) throws InterruptedException {
        ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(1);

        scheduler.scheduleWithFixedDelay(() -> {
            try {
                System.out.println("poll " + Instant.now());
            } catch (RuntimeException error) {
                error.printStackTrace();
            }
        }, 0, 1, TimeUnit.SECONDS);

        Thread.sleep(3200);
        scheduler.shutdown();
        if (!scheduler.awaitTermination(2, TimeUnit.SECONDS)) {
            scheduler.shutdownNow();
        }
    }
}
```

## 两种调度的差异

固定频率任务执行过慢时，不会并发执行同一个周期任务，但后续执行会尽快追赶计划；它也不会“补发”多个同时运行的实例。固定延迟则天然把任务耗时算在周期之外，不会追赶。

周期任务若抛出未捕获异常，后续执行会被抑制，因此示例在任务内部记录异常。生产代码还应设置执行超时、幂等边界与监控。关闭服务时先调用 `shutdown` 等待在途任务，再按策略决定是否 `shutdownNow`。调度器提供进程内计时，不保证进程重启后的补偿；需要持久可靠的定时任务时，应使用带持久状态的调度系统。
