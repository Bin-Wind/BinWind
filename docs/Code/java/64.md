# Java Semaphore：限制并发访问稀缺资源

线程池限制的是执行线程数量，但多个任务可能共同访问一个更稀缺的资源，例如只有三个连接名额的外部服务。`Semaphore` 用许可证表示容量，取得后才能进入，离开时必须归还。

```java
import java.util.concurrent.Semaphore;
import java.util.concurrent.TimeUnit;

public class SemaphoreDemo {
    private static final Semaphore SLOTS = new Semaphore(2, true);

    static void callService(int id) throws InterruptedException {
        boolean acquired = SLOTS.tryAcquire(500, TimeUnit.MILLISECONDS);
        if (!acquired) {
            System.out.println(id + " timed out");
            return;
        }
        try {
            System.out.println(id + " entered");
            Thread.sleep(200);
        } finally {
            SLOTS.release();
        }
    }

    public static void main(String[] args) throws InterruptedException {
        Thread[] threads = new Thread[5];
        for (int i = 0; i < threads.length; i++) {
            int id = i;
            threads[i] = new Thread(() -> {
                try {
                    callService(id);
                } catch (InterruptedException error) {
                    Thread.currentThread().interrupt();
                }
            });
            threads[i].start();
        }
        for (Thread thread : threads) thread.join();
    }
}
```

只有成功取得许可证后才能在 `finally` 中释放，否则会凭空增加容量。带超时的 `tryAcquire` 比无限等待更容易受控；被中断时恢复线程中断标记。

构造函数的公平模式会尽量按等待顺序发放许可证，减少饥饿，但可能降低吞吐。信号量不会验证归还者，也不是互斥锁的所有权模型。监控可用许可证、等待时间和超时率，才能判断容量是否合理。
