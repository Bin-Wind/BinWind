# structuredClone 深拷贝实战

`JSON.parse(JSON.stringify(value))` 常被当作深拷贝，但它会丢失 `Date`、`Map`、`Set`、`undefined` 等信息，并且无法处理循环引用。`structuredClone` 使用浏览器结构化克隆算法，覆盖更多内置类型。

## 基础示例

```js
const original = {
  createdAt: new Date('2026-01-01T00:00:00Z'),
  labels: new Set(['draft']),
  metadata: new Map([['count', 1]])
}

original.self = original
const copy = structuredClone(original)

console.log(copy !== original)                  // true
console.log(copy.createdAt instanceof Date)     // true
console.log(copy.self === copy)                 // true
```

函数、DOM 节点和部分宿主对象不能被克隆，会抛出 `DataCloneError`。类实例通常也不会保留自定义原型语义，因此它不是通用序列化器。

## 转移大缓冲区

无需保留原缓冲区时，可以转移所有权，避免复制：

```js
const buffer = new ArrayBuffer(1024)
const moved = structuredClone(buffer, { transfer: [buffer] })
console.log(buffer.byteLength) // 0
console.log(moved.byteLength)  // 1024
```

转移后原对象不可再使用，适合 Worker 之间传递大块二进制数据。

## 是否真的需要深拷贝

深拷贝大型状态成本很高。不可变更新通常只复制发生变化的路径，数据库实体则应通过明确 DTO 转换。先明确边界和所有权，再选择克隆；不要用深拷贝掩盖共享可变状态设计问题。
