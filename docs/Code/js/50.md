# TextDecoder 流式解码：避免 UTF-8 字符被分块截断

网络或文件流的字节块不保证落在 UTF-8 字符边界。每块单独 `decode()` 可能产生替换字符。持续使用同一个 `TextDecoder` 并传入 `{ stream: true }`，解码器会保留未完成字节。

```javascript
const decoder = new TextDecoder('utf-8', { fatal: true });

function decodeChunks(chunks) {
  let text = '';
  for (const chunk of chunks) {
    text += decoder.decode(chunk, { stream: true });
  }
  text += decoder.decode();
  return text;
}

const bytes = new TextEncoder().encode('你好，stream');
console.log(decodeChunks([bytes.slice(0, 1), bytes.slice(1, 5), bytes.slice(5)]));
```

`fatal: true` 会在无效编码时抛错，适合必须拒绝损坏输入的场景；默认模式会插入替换字符。选择哪种行为要写进协议。

## 不要无限拼接

大型流反复拼接字符串会增加内存。浏览器支持时可用 `TextDecoderStream`，或按完整行、完整消息逐步交给下游。分隔符也可能跨块，需要保留未完成尾段。

同一个 decoder 不应并发处理两条独立字节流，否则内部状态会串线。每条流创建一个实例，并在结束、取消和异常路径都丢弃状态。
