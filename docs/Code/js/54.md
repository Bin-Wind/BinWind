# Promise.withResolvers：把完成能力交给事件边界

有时 Promise 的完成来自外部事件，需要同时拿到 `promise`、`resolve` 和 `reject`。`Promise.withResolvers()` 可以避免在构造器回调外再声明变量。

```javascript
function once(target, successEvent, errorEvent = 'error') {
  const { promise, resolve, reject } = Promise.withResolvers()

  const cleanup = () => {
    target.removeEventListener(successEvent, onSuccess)
    target.removeEventListener(errorEvent, onError)
  }
  const onSuccess = event => { cleanup(); resolve(event) }
  const onError = event => { cleanup(); reject(event.error ?? new Error(errorEvent)) }

  target.addEventListener(successEvent, onSuccess, { once: true })
  target.addEventListener(errorEvent, onError, { once: true })
  return promise
}
```

它适合桥接回调或事件，不应成为随处可见的全局“完成开关”。解析函数若泄露给无关模块，任何代码都能过早完成任务，状态所有权会变得模糊。

Promise 只能结算一次，之后调用会被忽略，但相关监听器和计时器不会自动清理。实际封装应在成功、失败、超时和取消路径执行同一清理函数。若目标运行环境尚不支持该方法，可继续使用 `new Promise((resolve, reject) => ...)` 或由构建目标提供经过验证的兼容方案。
