# AbortSignal.throwIfAborted：在多阶段任务间快速响应取消

只把 `signal` 传给 `fetch` 不够：解析、转换和循环等同步阶段也可能在用户取消后继续消耗资源。`throwIfAborted()` 可在阶段边界立即抛出取消原因。

```javascript
async function buildReport(rows, { signal }) {
  signal.throwIfAborted()
  const normalized = []

  for (let index = 0; index < rows.length; index += 1) {
    if (index % 100 === 0) signal.throwIfAborted()
    normalized.push(String(rows[index]).trim())
  }

  signal.throwIfAborted()
  return normalized.join('\n')
}

const controller = new AbortController()
buildReport(['a', 'b'], { signal: controller.signal })
  .catch(error => {
    if (controller.signal.aborted) return
    throw error
  })
```

检查频率要在响应速度与循环开销间取平衡。长时间完全同步的计算即使检查信号，也会阻塞触发取消的事件；这类任务应拆分让出主线程，或放入 Worker 并设计终止协议。

取消不是普通故障。调用方应区分超时、用户主动取消和依赖失败，不对取消盲目重试。已经发生的外部写入不会因抛异常自动回滚，副作用步骤仍需幂等键、事务或补偿操作。
