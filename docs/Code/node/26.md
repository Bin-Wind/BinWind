# worker_threads 处理 CPU 密集任务

Node.js 的事件循环适合 I/O，但大规模计算会阻塞所有请求。`worker_threads` 能把 JavaScript 计算放到独立线程，适合图像处理、压缩和复杂计算。

## 可运行示例

创建 `worker.js`：

```js
const { parentPort, workerData } = require('node:worker_threads')

function fibonacci(n) {
  if (n < 2) return n
  return fibonacci(n - 1) + fibonacci(n - 2)
}

parentPort.postMessage(fibonacci(workerData))
```

创建 `main.js`：

```js
const { Worker } = require('node:worker_threads')
const path = require('node:path')

function runWorker(value) {
  return new Promise((resolve, reject) => {
    const worker = new Worker(path.join(__dirname, 'worker.js'), { workerData: value })
    worker.once('message', resolve)
    worker.once('error', reject)
    worker.once('exit', code => {
      if (code !== 0) reject(new Error(`worker stopped: ${code}`))
    })
  })
}

runWorker(35).then(console.log, console.error)
```

运行 `node main.js` 即可。生产代码要防止同一个 Promise 被错误与退出事件重复结算，可封装统一生命周期。

## 使用线程池

每个任务都创建 Worker 有启动成本。高频任务应维护固定大小的线程池、任务队列和背压；线程数从 CPU 核心数附近开始压测，而不是无限增加。

大量数据通过消息复制也很昂贵。可使用 Transferable 转移 `ArrayBuffer` 所有权，或谨慎使用 `SharedArrayBuffer`。普通数据库与 HTTP 等等待型任务不需要 Worker，异步 API 已足够。
