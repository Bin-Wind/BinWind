# Node.js 服务优雅关闭指南

容器滚动更新或进程收到终止信号时，立即退出会切断正在处理的请求。优雅关闭应停止接收新流量，等待在途任务，并在超时后强制结束。

## HTTP 服务示例

```js
const http = require('node:http')

const sockets = new Set()
const server = http.createServer((req, res) => {
  setTimeout(() => res.end('ok'), 100)
})

server.on('connection', socket => {
  sockets.add(socket)
  socket.on('close', () => sockets.delete(socket))
})

server.listen(3000)

let closing = false
function shutdown(signal) {
  if (closing) return
  closing = true
  console.log(`received ${signal}`)

  const timer = setTimeout(() => {
    for (const socket of sockets) socket.destroy()
    process.exitCode = 1
  }, 10_000)
  timer.unref()

  server.close(error => {
    clearTimeout(timer)
    if (error) process.exitCode = 1
  })
}

process.on('SIGTERM', () => shutdown('SIGTERM'))
process.on('SIGINT', () => shutdown('SIGINT'))
```

`server.close()` 停止接受新连接，并等待现有连接结束。部署平台还应先把实例从负载均衡健康列表移除，给路由传播留出时间。

## 清理顺序

先标记实例不就绪，再关闭监听端口，然后停止消费者、完成或归还消息，最后关闭数据库连接与遥测导出器。每一步都要有超时。

不要在信号处理函数里直接 `process.exit()`；它会跳过异步清理和缓冲日志。关闭逻辑必须幂等，因为本地开发或编排系统可能触发多个信号。
