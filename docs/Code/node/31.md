# Node.js 启动配置校验：让错误尽早暴露

环境变量都是字符串，缺失、空值和拼写错误往往直到请求到来才触发故障。应用应在启动阶段集中解析，之后只读取类型明确的配置对象。

```js
function required(name) {
  const value = process.env[name]?.trim()
  if (!value) throw new Error(`missing environment variable: ${name}`)
  return value
}

function integer(name, fallback) {
  const raw = process.env[name]
  if (raw === undefined) return fallback
  const value = Number(raw)
  if (!Number.isInteger(value) || value <= 0) {
    throw new Error(`${name} must be a positive integer`)
  }
  return value
}

export const config = Object.freeze({
  databaseUrl: required('DATABASE_URL'),
  port: integer('PORT', 3000),
})
```

布尔值不要用 `Boolean(process.env.DEBUG)`，因为字符串 `'false'` 也是真值；应显式接受有限集合。

错误信息可以包含变量名，不能打印密码、令牌或完整连接串。部署时由密钥管理系统注入敏感值，仓库只提交不含秘密的 `.env.example`。
