# Node.js 原生 fetch：超时、校验与错误边界

现代 Node.js 提供全局 `fetch`，但它只在网络层失败时抛错，HTTP 404 或 500 仍会正常返回响应。调用方必须主动检查状态并限制等待时间。

```javascript
async function getJson(url, timeoutMs = 3000) {
  const response = await fetch(url, {
    headers: { accept: 'application/json' },
    signal: AbortSignal.timeout(timeoutMs),
  })
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`)
  }
  const type = response.headers.get('content-type') ?? ''
  if (!type.includes('application/json')) {
    throw new TypeError(`unexpected content-type: ${type}`)
  }
  return response.json()
}

getJson('https://jsonplaceholder.typicode.com/todos/1')
  .then(console.log)
  .catch(console.error)
```

解析成功不等于数据结构正确，外部响应还应通过 Schema 校验。大文件使用响应流而不是一次 `json()` 或 `arrayBuffer()` 读入内存。

重试前区分超时、限流和业务错误，并给整个调用链设置总期限。日志记录目标主机、状态码和耗时，认证头、Cookie 与敏感正文应脱敏或省略。
