# Node.js HTTP 请求体限制：在解析前挡住超大输入

只在 JSON 解析后检查对象大小已经太晚，服务可能先耗尽内存。使用原生 HTTP 模块时，应在读取字节流的过程中累计大小并尽早终止。

```javascript
import http from "node:http";

const LIMIT = 64 * 1024;

http.createServer((request, response) => {
  let size = 0;
  const chunks = [];

  request.on("data", (chunk) => {
    size += chunk.length;
    if (size > LIMIT) {
      response.writeHead(413).end("Payload Too Large");
      request.destroy();
      return;
    }
    chunks.push(chunk);
  });

  request.on("end", () => {
    if (size > LIMIT) return;
    try {
      const body = JSON.parse(Buffer.concat(chunks).toString("utf8"));
      response.writeHead(200, { "content-type": "application/json" });
      response.end(JSON.stringify({ received: Boolean(body) }));
    } catch {
      response.writeHead(400).end("Invalid JSON");
    }
  });
}).listen(3000);
```

反向代理和应用都应设限制，但应用不能假设代理永远存在。压缩请求还要限制解压后的大小，避免压缩炸弹。

同时配置请求头超时、整体读取超时和并发上限。上传大文件不要把 Buffer 全部保存在内存，改用流式写入隔离临时区，并在内容校验完成后再移动到正式位置。
