# Node.js fs.cp：复制目录并用过滤器控制范围

Node.js 的 `fs/promises.cp` 可以递归复制目录，无需额外依赖。复制前要明确覆盖策略、符号链接语义和排除目录，尤其不能把缓存或秘密文件意外带进发布包。

```javascript
import { cp } from 'node:fs/promises';
import path from 'node:path';

const source = path.resolve('site');
const destination = path.resolve('dist/site');
const excluded = new Set(['.git', 'node_modules', '.env']);

await cp(source, destination, {
  recursive: true,
  errorOnExist: true,
  force: false,
  filter: (entry) => !excluded.has(path.basename(entry)),
});
```

`filter` 对目录返回 `false` 时会跳过其子树。仅按 basename 排除简单易懂，但若业务允许同名普通文件，需要改为相对路径规则。

## 不把复制当成事务

复制中途失败时，目标目录可能只完成一部分。稳妥流程是在同一文件系统的临时目录复制，校验文件清单后再原子改名；切换前不要让服务读取半成品。

目标路径必须先解析并验证，不能直接拼接用户输入。对符号链接要按部署需求测试：复制链接本身与跟随链接得到的内容不同，也可能越出源目录边界。完成后比较文件数量与摘要，而不是只看命令没有报错。
