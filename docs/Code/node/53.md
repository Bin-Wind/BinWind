# Node.js fs.watch：用 AbortSignal 管理监听器生命周期

`fs.watch` 适合收到“目录可能变化”的提示，但不同平台可能合并事件、缺少文件名或重复通知。它不是可靠审计日志，处理逻辑应在收到事件后重新扫描真实状态。

```javascript
import { watch } from 'node:fs';

const controller = new AbortController();
const watcher = watch('./inbox', { signal: controller.signal }, (event, filename) => {
  console.log({ event, filename: filename?.toString() ?? null });
  // 这里只触发一次带防抖的重新扫描
});

watcher.on('error', (error) => {
  console.error(error);
  controller.abort();
});

process.once('SIGINT', () => controller.abort());
```

取消信号可以把监听器与服务生命周期绑定，避免测试或热重载后残留句柄。关闭时仍应等待正在进行的扫描安全结束。

## 把事件当提示

编辑器常通过“写临时文件再重命名”保存，单次修改可能表现为多个事件。对文件名先做路径边界校验，不要因为监听目录可信就直接打开任意拼接路径。网络文件系统、容器挂载和文件被删除重建时行为可能不同。

需要保证每次变更都被消费时，使用应用级队列、数据库变更记录或定期全量对账；`fs.watch` 只负责降低发现延迟。
