# Node.js finished：确认流真正结束并清理监听器

流的 `end`、`finish` 和 `close` 含义不同。只监听其中一个事件容易漏掉提前销毁或错误。`node:stream/promises` 的 `finished` 返回 Promise，在流完成或失败时统一结束。

```javascript
import { createWriteStream } from 'node:fs';
import { finished } from 'node:stream/promises';

const output = createWriteStream('result.txt', { flags: 'wx' });

try {
  output.end('done\n');
  await finished(output, { cleanup: true });
  console.log('write completed');
} catch (error) {
  output.destroy();
  throw error;
}
```

`cleanup: true` 会在 Promise 结束后移除由 `finished` 添加的监听器，适合重复运行的任务。它不会验证文件内容、调用 `fsync` 或把临时文件发布为最终文件；这些是更高层的交付步骤。

## 与 pipeline 的区别

有读流到写流的传输时，优先使用 `pipeline`，它会传播错误并协调销毁。`finished` 更适合等待一个已经由其他代码驱动的流。若加入取消信号，取消后还要确认底层资源确实关闭，并区分用户取消与真实 I/O 故障。
