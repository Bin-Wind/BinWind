# Node.js captureRejections：集中处理异步监听器拒绝

`EventEmitter` 不会等待异步监听器返回的 Promise。监听器抛错后产生的拒绝若无人处理，可能变成未处理拒绝。创建实例时启用 `captureRejections`，Node.js 会把异步监听器的拒绝转交给该发射器的 `error` 事件。

```javascript
import { EventEmitter } from 'node:events'

const jobs = new EventEmitter({ captureRejections: true })

jobs.on('task', async (task) => {
  if (!task.id) throw new Error('task.id 缺失')
  await Promise.resolve()
  console.log('processed', task.id)
})

jobs.on('error', (error) => {
  console.error('listener failed:', error.message)
})

jobs.emit('task', { id: '' })
```

必须注册 `error` 监听器；若 `error` 事件无人处理，进程仍可能终止。错误处理器本身不要写成会拒绝的异步函数，否则可能形成新的错误循环。需要异步上报时，在同步处理器中显式启动并捕获上报 Promise。

## 它不是任务完成通知

`emit()` 仍然同步返回布尔值，不会等待监听器完成，也不会把监听器结果汇总给调用方。若业务必须知道所有任务是否成功，应直接调用返回 Promise 的函数，或建立显式任务队列，而不是依赖事件发射器。

可在单个实例上启用该选项，避免全局改变所有 EventEmitter 的行为。测试时覆盖同步抛错、异步拒绝和 `error` 处理器存在与否，确认错误最终落到可观测且不会递归失败的边界。
