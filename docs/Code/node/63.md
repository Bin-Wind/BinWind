# Node.js AsyncLocalStorage：跨异步调用传递请求上下文

记录请求 ID 时，把参数从路由层一路传到数据库层会污染大量函数签名。`AsyncLocalStorage` 可以为一条异步调用链保存上下文，让深层代码读取当前请求信息。

```javascript
import { AsyncLocalStorage } from 'node:async_hooks'
import { randomUUID } from 'node:crypto'

const requestContext = new AsyncLocalStorage()

function log(message) {
  const context = requestContext.getStore()
  console.log(JSON.stringify({
    requestId: context?.requestId ?? null,
    message,
  }))
}

async function handleRequest() {
  await Promise.resolve()
  log('query completed')
}

await requestContext.run({ requestId: randomUUID() }, handleRequest)
```

`run` 只在回调及其创建的异步资源中提供值，回调完成后上下文自动退出。不要使用一个可变全局对象承载所有请求，也不要把密码、令牌或完整用户资料放进上下文。

## 明确边界

某些自行管理回调或原生扩展可能丢失异步上下文，接入后要通过并发测试验证：同时发出多个请求，日志中的 ID 不应串线。后台任务脱离 HTTP 请求后应创建新的上下文，而不是长期继承已结束请求。

上下文方便可观测性，但业务授权函数最好仍接收明确的主体参数，避免关键权限依赖不可见状态。请求结束后也不要保存 `getStore()` 返回对象的长期引用。
