# Node.js stream.pipeline：让流错误统一收口

手工调用多个 `pipe()` 时，每一段流都可能失败，遗漏任一错误监听就会留下半写文件或未关闭资源。`node:stream/promises` 的 `pipeline` 把完成与错误汇总为一个 Promise，并在失败时销毁相关流。

```javascript
import { createReadStream, createWriteStream } from 'node:fs'
import { pipeline } from 'node:stream/promises'
import { createGzip } from 'node:zlib'

async function compress(source, target, signal) {
  await pipeline(
    createReadStream(source),
    createGzip(),
    createWriteStream(target, { flags: 'wx' }),
    { signal },
  )
}

const controller = new AbortController()
try {
  await compress('input.log', 'input.log.gz', controller.signal)
  console.log('压缩完成')
} catch (error) {
  console.error('压缩失败:', error.message)
}
```

`flags: 'wx'` 会在目标已存在时失败，避免无意覆盖。生产代码可先写入同目录临时文件，`pipeline` 成功并完成校验后再原子重命名；失败时清理临时文件。

背压会沿管道传递，写入端变慢时读取端不会无限灌入内存。`pipeline` 结束表示流链已完成，不等于业务数据一定正确；压缩、上传等任务仍可校验字节数、摘要或下游确认。取消信号会中止管道，但外部副作用是否回滚需由业务处理。
