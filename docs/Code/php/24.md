# PDO 事务：保证多步写入一致

当一个业务动作需要修改多张表时，任何一步失败都应回滚。PDO 提供统一事务接口，但事务边界仍需由业务代码明确控制。

## 转账示例

```php
<?php
$pdo = new PDO(
    'sqlite:' . __DIR__ . '/demo.sqlite',
    null,
    null,
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$pdo->exec('CREATE TABLE IF NOT EXISTS account (
    id INTEGER PRIMARY KEY, balance INTEGER NOT NULL CHECK(balance >= 0)
)');
$pdo->exec('INSERT OR IGNORE INTO account(id, balance) VALUES (1, 1000), (2, 500)');

try {
    $pdo->beginTransaction();
    $amount = 200;
    $debit = $pdo->prepare(
        'UPDATE account SET balance = balance - :amount WHERE id = :id AND balance >= :amount'
    );
    $debit->execute(['amount' => $amount, 'id' => 1]);
    if ($debit->rowCount() !== 1) {
        throw new RuntimeException('余额不足或账户不存在');
    }

    $credit = $pdo->prepare('UPDATE account SET balance = balance + :amount WHERE id = :id');
    $credit->execute(['amount' => $amount, 'id' => 2]);
    if ($credit->rowCount() !== 1) throw new RuntimeException('收款账户不存在');
    $pdo->commit();
} catch (Throwable $error) {
    if ($pdo->inTransaction()) $pdo->rollBack();
    throw $error;
}
```

金额用最小货币单位的整数表示，避免浮点误差。条件更新同时检查余额，减少“先查再改”的竞态窗口。

## 实战注意

事务尽量短，不要在事务内调用慢外部 API。网络调用无法随数据库一起回滚，需用事务发件箱或补偿任务协调。针对死锁与瞬时冲突可以有限重试，但要使用幂等业务编号防止重复入账。
