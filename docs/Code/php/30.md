# PHP readonly DTO：在输入边界固定数据

数组传递方便，但键名拼错、字段缺失和中途修改都难追踪。只读数据传输对象适合在控制器解析输入后，把合法数据交给业务层。

```php
<?php
declare(strict_types=1);

readonly class CreateUser
{
    public function __construct(
        public string $name,
        public string $email,
    ) {
        if ($name === '') {
            throw new InvalidArgumentException('姓名不能为空');
        }
        if (filter_var($email, FILTER_VALIDATE_EMAIL) === false) {
            throw new InvalidArgumentException('邮箱格式错误');
        }
    }
}

$command = new CreateUser('小林', 'lin@example.com');
echo $command->email, PHP_EOL;
```

`readonly` 阻止属性重新赋值，但不会自动让属性引用的对象深度不可变。DTO 只承载经过规范化的数据，不负责数据库查询或发送邮件。

HTTP JSON 输入先检查解码错误和字段类型，再构造对象。不要直接用展开运算符把未经筛选的请求数组传入构造器，否则额外字段会让接口升级变得不可控。
