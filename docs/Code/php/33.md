# PHP Webhook 签名验证：先验真再解析业务

Webhook 端点公开可访问，不能只依赖难猜的 URL。发送方通常用共享密钥对原始请求体做 HMAC，接收方必须在处理 JSON 前验证。

```php
<?php
declare(strict_types=1);

$secret = getenv('WEBHOOK_SECRET');
if ($secret === false || $secret === '') {
    http_response_code(500);
    exit;
}

$body = file_get_contents('php://input');
$provided = $_SERVER['HTTP_X_SIGNATURE'] ?? '';
$expected = hash_hmac('sha256', $body, $secret);

if (!hash_equals($expected, $provided)) {
    http_response_code(401);
    exit;
}

$event = json_decode($body, true, flags: JSON_THROW_ON_ERROR);
http_response_code(204);
```

签名必须基于未经重新编码的原始字节，`hash_equals` 可避免普通字符串比较的时序差异。具体头名、编码和拼接格式以提供方文档为准。

生产端点还应校验时间戳并限制允许偏差，防止旧请求重放；用事件 ID 建唯一约束保证幂等。先快速持久化已验证事件再异步处理，响应超时不应导致业务执行多次。密钥轮换期间可短暂接受新旧两个密钥，但日志绝不能记录它们。
