# PHP filter_var：验证邮箱与 URL 的输入边界

验证的目标是判断输入是否符合当前接口约定，不是把任意字符串“清洗”成看似合法的值。保留原始输入用于错误提示，再对规范化结果做验证。

```php
<?php
declare(strict_types=1);

$email = trim(' user@example.com ');
if (filter_var($email, FILTER_VALIDATE_EMAIL) === false) {
    throw new InvalidArgumentException('邮箱格式不正确');
}

$url = 'https://example.com/docs';
if (filter_var($url, FILTER_VALIDATE_URL) === false) {
    throw new InvalidArgumentException('URL 格式不正确');
}
$parts = parse_url($url);
if (($parts['scheme'] ?? '') !== 'https') {
    throw new InvalidArgumentException('只允许 HTTPS');
}
echo $email . PHP_EOL;
```

格式合法不代表邮箱存在或 URL 安全。服务器代用户请求 URL 时还要防 SSRF：限制协议与目标域名，解析 DNS 后阻止内网地址，并在重定向后再次检查。业务枚举和长度限制应显式实现，不要期待一个过滤器覆盖全部规则。
