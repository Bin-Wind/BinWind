# PHP set_error_handler：把可恢复错误纳入异常流程

旧式 PHP API 可能用 warning 报告失败，调用方容易漏掉返回值。可在受控边界临时注册错误处理器，将当前错误转换为 ErrorException。

~~~php
<?php
declare(strict_types=1);

set_error_handler(function (int $severity, string $message, string $file, int $line): bool {
    if (!(error_reporting() & $severity)) return false;
    throw new ErrorException($message, 0, $severity, $file, $line);
});
try {
    $data = file_get_contents(__DIR__ . '/missing.txt');
    echo $data;
} catch (ErrorException $error) {
    fwrite(STDERR, $error->getMessage() . PHP_EOL);
} finally {
    restore_error_handler();
}
~~~

处理器不是全局万能开关；它不能捕获所有引擎错误，也不应把预期业务分支都变成异常。库代码若临时安装处理器，必须在 finally 中恢复。生产环境向用户隐藏路径和堆栈，详细信息只进入受控日志。
