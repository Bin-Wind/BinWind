# PHP register_shutdown_function：记录致命退出但不冒充恢复

`register_shutdown_function` 可在脚本结束时执行清理或检查最后错误。它常用于记录某些致命错误，但此时应用状态可能已经不完整，不能继续正常业务流程。

```php
<?php
declare(strict_types=1);

register_shutdown_function(function (): void {
    $error = error_get_last();
    if ($error === null) {
        return;
    }

    $fatalTypes = [E_ERROR, E_PARSE, E_CORE_ERROR, E_COMPILE_ERROR];
    if (in_array($error['type'], $fatalTypes, true)) {
        error_log(json_encode([
            'event' => 'fatal_shutdown',
            'type' => $error['type'],
            'file' => basename($error['file']),
            'line' => $error['line'],
        ], JSON_THROW_ON_ERROR));
    }
});
```

示例刻意不记录错误消息全文，因为它可能包含敏感输入。真实项目应把请求 ID 等安全上下文加入结构化日志，但避免令牌、Cookie 和请求体。

## 清理必须可重复

关闭函数执行时，输出可能已发送，内存也可能耗尽。只做短小、幂等、低依赖的操作；不要发复杂网络请求或尝试继续数据库事务。关键数据应在正常流程中及时提交或回滚，不能把 shutdown 当作事务保证。

进程被强制终止、机器断电等情况下，关闭函数不一定运行。可靠任务仍需外部租约、幂等键和恢复机制。
