# PHP Filter API：校验输入而不是悄悄修正

用户输入是字符串，但业务通常需要整数、布尔值或地址。Filter API 可以完成常见校验；关键是区分“校验失败”与“过滤后得到另一个值”，并避免依赖宽松类型转换。

```php
<?php
function parsePage(mixed $value): int
{
    $result = filter_var(
        $value,
        FILTER_VALIDATE_INT,
        ['options' => ['min_range' => 1, 'max_range' => 1000]]
    );
    if ($result === false) {
        throw new InvalidArgumentException('page 必须是 1 到 1000 的整数');
    }
    return $result;
}

foreach (['1', '20', '0', '2.5', 'abc'] as $input) {
    try {
        echo parsePage($input), PHP_EOL;
    } catch (InvalidArgumentException $error) {
        echo $error->getMessage(), PHP_EOL;
    }
}
```

不能用 `if (!$result)` 判断，因为合法整数可能是 `0`；应使用严格比较 `=== false`，并根据业务范围决定零是否允许。

`FILTER_VALIDATE_URL` 只判断语法，不证明地址可访问或安全。接受回调 URL 时仍要限制协议、解析主机、处理 DNS 变化并阻止访问内网。邮箱校验也不证明邮箱存在。Filter API 是输入边界的一层，不替代领域规则、授权与数据库约束。

先保留原始输入用于错误反馈，再将已验证值转换为明确类型。不要为了“让它通过”而静默删除字符，否则用户输入错误会变成另一条看似合法的数据。
