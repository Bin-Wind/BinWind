# asyncio 并发请求与超时控制

`asyncio` 适合大量等待型任务，例如 HTTP、数据库和消息队列 I/O。它不会让 CPU 计算自动变快；事件循环只有一个线程，协程必须在等待时主动让出控制权。

## 可运行示例

下面只用标准库模拟三个耗时任务，并给整个任务组设置超时：

```python
import asyncio

async def fetch(name: str, delay: float) -> str:
    await asyncio.sleep(delay)
    return f"{name}: done"

async def main() -> None:
    tasks = [
        asyncio.create_task(fetch("a", 0.2)),
        asyncio.create_task(fetch("b", 0.1)),
        asyncio.create_task(fetch("c", 0.3)),
    ]
    try:
        async with asyncio.timeout(1):  # Python 3.11+
            results = await asyncio.gather(*tasks)
            print(results)
    except TimeoutError:
        for task in tasks:
            task.cancel()
        await asyncio.gather(*tasks, return_exceptions=True)

asyncio.run(main())
```

`gather` 按传入顺序返回结果，而不是完成顺序。若希望结果一完成就处理，可使用 `asyncio.as_completed`。

## 限制并发量

真实接口通常不能承受无限并发。用信号量包住外部调用：

```python
limit = asyncio.Semaphore(10)

async def bounded(call):
    async with limit:
        return await call()
```

超时应分层设置：连接、单次读取、单任务和整批任务分别有边界。取消协程后要等待其清理完成，避免连接泄漏。

## 何时不用 asyncio

CPU 密集计算应交给进程池或专用计算服务；少量顺序任务用同步代码更容易维护。不要在协程中调用 `time.sleep()` 或阻塞文件操作，否则整个事件循环都会停住。
