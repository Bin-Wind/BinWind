# 用 pyproject.toml 打包 Python 项目

现代 Python 项目可把构建系统、项目元数据和工具配置集中到 `pyproject.toml`。最小目录结构如下：

```text
demo-project/
  pyproject.toml
  src/demo_project/__init__.py
  tests/
```

`src` 布局能避免测试时误把仓库根目录当作已安装包。

## 最小配置

```toml
[build-system]
requires = ["setuptools>=69"]
build-backend = "setuptools.build_meta"

[project]
name = "demo-project"
version = "0.1.0"
description = "A small example package"
requires-python = ">=3.11"
dependencies = []

[project.scripts]
demo = "demo_project:main"
```

对应的 `src/demo_project/__init__.py`：

```python
def main() -> None:
    print("hello from demo-project")
```

## 构建与检查

```bash
python -m pip install --upgrade build twine
python -m build
python -m twine check dist/*
python -m pip install --editable .
demo
```

`python -m build` 会生成源码包和 wheel；`twine check` 检查包元数据与 README 渲染。发布前应在干净虚拟环境中安装 wheel 并运行测试。

## 版本与依赖

库项目宜声明兼容范围，不应提交某台机器的完整环境快照作为公共依赖。应用项目则需要锁文件保证部署一致。版本号应与发布标签一致，自动化发布时由单一来源生成，避免代码、标签和包名三处不一致。
