# sqlite3 事务：让多步写入一起成功或失败

库存扣减和流水写入必须保持一致。Python 标准库 `sqlite3` 的连接上下文会在正常结束时提交，发生异常时回滚。

```python
import sqlite3

def reserve(db_path: str, sku: str, quantity: int) -> None:
    with sqlite3.connect(db_path) as conn:
        cursor = conn.execute(
            "UPDATE inventory SET stock = stock - ? "
            "WHERE sku = ? AND stock >= ?",
            (quantity, sku, quantity),
        )
        if cursor.rowcount != 1:
            raise ValueError("库存不足或商品不存在")
        conn.execute(
            "INSERT INTO inventory_log(sku, quantity) VALUES (?, ?)",
            (sku, -quantity),
        )
```

值始终通过占位符绑定，表名等标识符不能这样绑定，若必须动态选择应使用白名单。条件更新把“检查库存”和“扣减”合成一次原子操作，避免先查后改的竞争窗口。

事务尽量短，不要在持锁期间发网络请求。并发写入场景可设置合理的连接超时，并在应用层有限重试 `database is locked`；长期高写入压力则应评估服务器型数据库。
