# functools.cache：缓存纯函数并避免陈旧结果

缓存适合输入相同就必然得到相同输出的昂贵函数。标准库装饰器能减少重复计算，但不理解数据库更新、时间变化或用户权限。

```python
from functools import lru_cache

@lru_cache(maxsize=256)
def parse_price(text: str, decimal_places: int) -> int:
    whole, dot, fraction = text.partition(".")
    normalized = (fraction + "0" * decimal_places)[:decimal_places]
    if not whole.isdigit() or (fraction and not fraction.isdigit()):
        raise ValueError("价格格式错误")
    return int(whole) * 10**decimal_places + int(normalized or "0")

print(parse_price("12.30", 2))
print(parse_price.cache_info())
```

参数必须可哈希，并且会成为缓存键的一部分。可变列表应先规范化为元组，但不要为了缓存而忽略本该区分的租户、语言或配置版本。

`cache` 相当于没有大小上限的 LRU 缓存，长生命周期服务更适合显式 `maxsize`。外部数据变化时，把版本号放进参数或调用 `cache_clear()`；只设置时间过期仍可能在窗口内返回旧数据。

缓存命中并不保证业务正确。监控命中率、条目数和计算耗时，确认节省的成本大于内存与失效复杂度。
