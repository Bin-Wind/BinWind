# Python ExceptionGroup：一次报告多个并发失败

并发任务可能同时失败。只抛出第一个异常会遮住其他问题，Python 3.11 引入的 `ExceptionGroup` 能把多个异常作为一个结构化对象传播，并用 `except*` 按类型处理。

```python
def validate(config: dict) -> None:
    errors = []
    if "host" not in config:
        errors.append(KeyError("缺少 host"))
    if config.get("workers", 0) < 1:
        errors.append(ValueError("workers 必须大于 0"))
    if errors:
        raise ExceptionGroup("配置无效", errors)

try:
    validate({"workers": 0})
except* KeyError as group:
    for error in group.exceptions:
        print("字段错误:", error)
except* ValueError as group:
    for error in group.exceptions:
        print("取值错误:", error)
```

## `except*` 的语义

每个 `except*` 接收匹配的子组；未匹配异常会继续向外传播。它不是普通 `except` 的别名，也不能在同一个 `try` 中混用两类语句。处理时保留异常链和 traceback，不要只拼接字符串后丢掉类型。

## 与 TaskGroup 配合

`asyncio.TaskGroup` 中多个子任务失败时会抛出异常组。某个任务失败后，其余任务通常会被取消，因此“所有任务都失败”不等于每个任务都独立跑到结尾。清理代码仍要正确响应取消。

异常组适合批量校验和结构化并发，不适合把无关错误无限堆积后继续运行。能立即阻止危险副作用的错误仍应尽早失败。
