# Python shlex：解析类 Shell 参数而不启动 Shell

配置中若允许用户写一串命令参数，直接用 `text.split()` 会破坏引号内空格；把字符串交给 `shell=True` 又会引入命令注入风险。`shlex.split()` 可以按类 POSIX Shell 规则拆分，再把参数列表直接传给子进程。

```python
import shlex
import subprocess

raw = '--title "季度 报告" --limit 10'
arguments = shlex.split(raw)

completed = subprocess.run(
    ["python", "report.py", *arguments],
    check=True,
    timeout=30,
    text=True,
)
print(completed.returncode)
```

这里没有启动 Shell，所以 `;`、`$()` 等不会被解释为管道或命令替换。不过它们仍可能成为被调用程序的普通参数；应用必须对白名单选项、路径范围和数值上限继续验证。

## 展示与执行分开

`shlex.join(arguments)` 可生成适合日志或复制的命令展示，但展示字符串不应再以 `shell=True` 执行。日志还要隐藏令牌、密码等敏感值。

Windows 原生命令行的引用规则与 POSIX 不完全相同，不能假设 `shlex` 能模拟所有目标程序。跨平台工具优先从一开始就接收参数数组，只有读取人类输入的类 Shell 文本时才使用 `shlex.split()`。
