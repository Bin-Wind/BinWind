# Vue provide/inject：为组件树提供类型安全的服务

当主题、表单上下文或领域服务要跨多层组件共享时，逐层传递 Props 会制造无意义的中转。`provide/inject` 适合组件树内依赖，但应使用 Symbol 避免键冲突。

```ts
// counter.ts
import type { InjectionKey, Ref } from 'vue'
export interface CounterService { count: Readonly<Ref<number>>; increment(): void }
export const counterKey: InjectionKey<CounterService> = Symbol('counter')
```

提供方负责状态与修改方法：

```ts
const count = ref(0)
provide(counterKey, {
  count: readonly(count),
  increment: () => { count.value += 1 },
})
```

消费方对缺失依赖显式失败：`const service = inject(counterKey); if (!service) throw new Error('missing provider')`。不要给关键服务一个看似可用的假默认值，它会掩盖组件挂载位置错误。

共享状态只在当前子树生效，这是它与全局 Pinia 的区别。测试组件时提供轻量替身即可，不必启动整套应用。
