# 空状态、加载态与错误态设计

界面不只有“有数据”的理想状态。初次使用、请求中、权限不足、网络失败和搜索无结果都会改变用户下一步，应该在设计阶段与主流程一起定义。

## 空状态不是一种状态

- **首次为空**：解释这里会出现什么，并提供创建入口。
- **筛选为空**：保留筛选条件，提供清除或调整建议。
- **权限为空**：说明需要什么权限以及如何申请。
- **完成为空**：例如收件箱清零，应确认任务已完成而非暗示故障。

文案要回答“发生了什么、为什么、现在能做什么”。主按钮只承载最可能的下一步。

## 加载策略

预计很快完成时可用轻量进度反馈；布局明确的内容用骨架屏减少跳动；长任务显示阶段或可理解的进度，并允许用户离开后再回来。不要让无限旋转图标掩盖无超时请求。

## 错误设计

错误应靠近发生位置，保留用户已经填写的内容，并提供可执行恢复动作。区分可重试的网络问题、需要修改输入的校验问题和需要管理员处理的权限问题。错误码可供支持人员定位，但不能替代人能读懂的说明。

## 交付状态矩阵

按页面列出 `initial / loading / success / empty / partial / error / offline`，标注触发条件、文案、操作和焦点位置。设计评审时用慢网、无权限和服务失败逐一走查，比只看静态成功稿更能发现真实体验断点。
