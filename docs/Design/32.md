# 权限设置界面：让用户看懂谁能做什么

权限页不是一排开关。用户真正想知道的是“谁、对哪个对象、能做什么”，以及修改会影响哪些人。界面应围绕这四个问题组织信息。

## 用角色解释能力

角色名称旁列出关键能力，例如“编辑者：可修改内容，不可管理成员”，并提供完整权限明细。不要只用“高级”“标准”等无法推断行为的标签。继承权限要显示来源，如“来自项目组”，避免用户找不到关闭入口。

## 让高风险变化可预见

删除管理员、公开分享或批量撤权前，摘要展示对象、人数和影响。确认按钮写具体动作，例如“撤销 18 人访问权”，而不是“确定”。危险操作与普通保存分开，防止连续点击误触。

保存后显示生效结果，并为短时间内可逆的修改提供撤销。若权限需要异步传播，明确显示“处理中”和预计状态，不要提前宣称成功。

可用性测试应覆盖：邀请新成员、追踪继承来源、撤销某人权限、判断链接是否公开。测试者能完成操作还不够，还应能准确复述最终谁拥有访问权。
