# 破坏性操作确认：让用户看懂将失去什么

删除、覆盖、撤销访问或终止服务都可能造成不可逆影响。确认界面的任务不是多放一个弹窗，而是在最后一步展示准确对象、影响范围和恢复方式。

## 根据风险选择摩擦

可撤销的小操作可直接执行并提供短时撤销；批量删除、永久清除或影响他人的操作需要明确确认。对极高风险动作，可要求输入资源名称，但不应把输入“DELETE”当成通用仪式。

对话框应包含：

- 动作与对象：“永久删除项目「秋季发布」”；
- 影响范围：“12 位成员将失去访问，3 个自动化停止”；
- 是否可恢复及保留期限；
- 明确按钮：“永久删除项目”，而不是“确定”。

主按钮颜色只提供辅助信号，文字必须独立表达结果。取消按钮保持容易找到，默认焦点不应落在破坏性动作上。

## 防止状态在确认时变化

确认页展示的对象版本应与提交动作绑定。若成员数或资源状态已变化，重新计算影响并请用户复核，不能用旧摘要执行新状态。

批量操作先提供清单和导出，完成后给出结果明细：成功、跳过、失败分别统计。可恢复操作应把“撤销”放在即时反馈中，并通过真实键盘、屏幕阅读器和误点场景测试。
