# 骨架屏设计：稳定布局而不是制造虚假速度

骨架屏适合结构已知且等待较短的内容加载。它的价值是保留空间和展示页面结构，不是用大量闪烁动画掩盖长期等待。

## 与真实内容共用布局约束

骨架块应接近最终图片比例、标题行数和卡片高度，避免内容到达后发生布局跳动。未知数量的列表只展示少量占位；无法预测结构时，用进度指示和说明文字更诚实。

动画保持轻柔，并尊重减少动态效果偏好。骨架元素通常不应进入辅助技术的阅读顺序；加载容器可暴露忙碌状态，完成后再公告有意义的内容。错误或空结果必须替换骨架，不能永久停留。

慢网测试要覆盖首次加载、分页加载、局部刷新和图片失败。监测布局偏移与实际等待时间；若数据来自本地且瞬间可得，短暂闪现骨架反而造成抖动，可设置很短的显示延迟避免闪烁。
