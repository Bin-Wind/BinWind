# 骨架屏设计：只预告稳定结构，不制造虚假进度

骨架屏适合布局已知、预计短暂等待的内容。它能减少页面跳动，却不能让慢请求真正变快；结构画得过细，还会让用户误以为数据即将出现。

骨架形状应对应最终卡片、头像和文本区域，尺寸保持一致，避免加载结束后整体位移。未知数量用少量代表项，不要铺满整屏。动画保持低对比、可关闭，并尊重 prefers-reduced-motion；长时间加载应转为明确状态，说明正在等待什么并提供重试或退出。

已有内容刷新时尽量保留旧结果并标记更新中，不必把整个页面重新变灰。失败后骨架必须结束，显示错误原因和恢复动作。测试快速缓存、慢网、空数据与失败四种路径，确保状态不会一闪而过或永久停留。
