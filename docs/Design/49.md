# 批量操作反馈：选择、执行与部分失败都要可追踪

批量操作不是把单条按钮放大。用户首先要知道选中了哪些对象、操作作用于当前页还是全部结果，以及筛选变化后选择是否仍保留。

执行前显示对象数量和不可逆影响，高风险动作提供可核对的名称或范围。长任务提交后立即返回任务状态，让用户可以离开页面；进度应区分排队、处理中、成功、跳过和失败，而不是一个永远接近完成的百分比。

部分失败时保留成功结果，不要求全部重做。失败列表包含对象、原因和可执行的下一步，并支持只重试失败项；重试必须复用幂等标识，避免成功项被重复处理。

完成摘要写清“成功 87、跳过 5、失败 8”，并允许导出明细。用跨页选择、权限变化、对象已删除、网络中断和重复点击测试，确保界面状态与后台真实状态一致。
