# 组件状态矩阵：把悬停、禁用与错误一次设计完整

只画默认状态，开发时就会临时猜测悬停、聚焦、加载和错误反馈。状态矩阵把组件可能的交互状态与内容变化放在一起检查，避免设计稿看似完整、实际流程却有空洞。

## 先列正交维度

按钮可有默认、悬停、键盘聚焦、按下、禁用和加载；输入框还包括空、有值、只读、校验错误与成功。不要为所有组合都画一张图，而要识别可以同时存在的维度，例如“键盘聚焦 + 错误”必须同时看得见。

矩阵中记录视觉、文案、可操作性、辅助技术名称和状态转换。禁用状态若用于解释为何不可用，应在附近提供原因；加载按钮需保持宽度并防止重复提交，但不能永久失去可取消或恢复路径。

## 用代表性内容验收

分别放入最短、最长、本地化和异常内容，检查布局是否抖动、图标是否成为唯一信号。悬停不能承载触屏用户必须知道的信息，颜色也不能独自表达错误。

交付时把矩阵链接到组件实现与测试用例。用鼠标、键盘和触屏走完关键转移，再模拟慢请求与失败。新增状态若无法放进已有矩阵，先判断它是否真是新状态，还是现有状态命名不清。
