# 高信息密度界面：用层级和对齐代替一味缩小

运营台和监控页需要同时看到大量数据，但密度不等于把字号、间距都压到最低。过度压缩会增加串行阅读和误点成本，反而降低处理速度。

先按任务排列信息：识别对象、判断状态、比较指标、执行动作。把稳定标签与变化值对齐，数字使用一致单位和小数位；相关列靠近，无关组用留白或弱分隔区分。次要元数据可按需展开，但异常原因和关键动作不能藏在悬停中。

表格行高应同时满足可读性与目标设备的点击精度。提供舒适、紧凑等有限密度档位时，列宽、截断和固定表头需一起测试，不能只改 padding。颜色用于辅助分组，不独自表达状态。

用真实的长名称、极值、空值和多语言内容验收，并让目标用户完成查找与比较任务。记录完成时间、误选率和滚动次数，比询问“看起来是否专业”更能判断密度是否合适。
