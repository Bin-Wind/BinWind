# 批量操作反馈：让用户知道选中了什么、改变了什么

批量删除、归档或改状态的风险来自作用范围不清。操作栏应持续显示已选数量，并说明选择仅限当前页、当前筛选结果，还是跨页全部结果。

执行前的确认文案要写出动作、对象范围和不可逆后果，例如“归档筛选出的 248 个订单”，而不是笼统的“确定吗”。若数量在后台发生变化，提交时重新计算并提示差异，不能沿用过期计数。

长任务提交后立即返回任务状态，展示成功、跳过与失败数量。部分失败需要提供可下载的对象清单和重试入口，重试只包含失败项。可撤销动作使用有明确期限的撤销，而不可逆动作需提高确认强度并限制权限。

测试空选择、跨页选择、筛选变化、并发编辑和网络重试。复选框的可访问名称应包含对象身份，焦点在操作结束后回到可预测位置。透明的范围与结果比一条“操作成功”通知更重要。
