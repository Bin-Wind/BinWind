# 表单自动保存状态：把等待、成功与失败说清楚

自动保存消除了“保存”按钮，也拿走了用户判断数据是否安全的线索。界面至少要区分未提交、更改中、保存中、已保存、离线等待和保存失败。

## 状态要对应真实事件

输入后可短暂显示“有未保存更改”，防抖结束并发出请求后变为“正在保存”；只有服务器确认版本已持久化才能显示“已保存”。网络断开时写“将在恢复连接后重试”，不要把本地草稿冒充云端成功。

## 避免提示闪烁

快速连续输入时合并请求，并使用版本号或请求序列阻止旧响应覆盖新状态。“已保存”可保持可见但降低强调，不必每次弹出通知。失败提示应贴近状态区域，给出重试和复制内容的出口，不能只在几秒后消失。

测试用例要覆盖慢网、离线、跨标签页编辑、权限过期和服务端冲突。关闭页面前若仍有未持久化内容，明确告知风险；若本地草稿可恢复，也要说明保存位置与保留范围。
