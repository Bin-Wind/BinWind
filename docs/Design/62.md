# 空状态设计：解释发生了什么并给出下一步

列表为空不只有一种原因：新用户从未创建内容、筛选条件没有命中、数据加载失败，或用户没有权限。若都显示“暂无数据”，用户无法判断该等待、修改条件还是开始创建。

## 按原因设计

首次使用的空状态应简短说明页面价值，并提供一个主要动作，例如“创建第一个项目”；搜索无结果要回显关键词、提供清除筛选或修改拼写；权限为空则解释可见范围和申请入口；错误状态应保留重试及诊断信息，不能伪装成正常空白。

每个空状态至少回答三件事：

1. 现在为什么没有内容；
2. 用户可以做什么；
3. 操作后会发生什么。

插画只能辅助情绪，不能替代文字与动作。主要按钮不宜超过一个，次要帮助以链接呈现。若用户根本无权创建，就不要放一个点击后才报错的“新建”按钮。

## 验收转换过程

测试从有数据到筛选为空、从离线到重试成功、从无权限到授权后的状态转换。异步加载开始时避免短暂闪现空状态，可先显示与页面结构一致的加载占位。辅助技术应能读到状态变化，焦点不要在内容出现后突然丢失。

好的空状态不是装饰性的终点，而是对当前系统状态的诚实解释和一条低摩擦的下一步路径。
