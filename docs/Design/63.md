# 键盘焦点顺序：让操作路径与视觉结构一致

只用键盘访问页面时，焦点顺序就是界面的阅读与操作顺序。视觉上从上到下排列，Tab 却先跳到右下角，会让用户失去位置感；这通常来自 DOM 顺序与 CSS 排列不一致。

## 以文档顺序为主

先让 DOM 按标题、说明、输入与操作的合理顺序排列，再使用 Grid 或 Flex 做视觉布局。不要依赖正数 `tabindex` 人工拼接顺序，它很快会在组件插入后失控。原生按钮、链接和表单控件已具备正确焦点行为，`div` 加点击事件不能自动获得这些能力。

焦点样式需要在不同背景上清晰可见，并与悬停状态区分。不要全局移除 `outline`；若自定义，至少提供足够对比和外侧空间。隐藏或禁用元素不应继续进入 Tab 序列。

## 动态界面的焦点管理

打开模态框后将焦点移到有意义的起点，并限制在对话框内；关闭后返回触发按钮。删除当前焦点所在的列表项时，把焦点放到相邻项或列表标题，而不是落到页面顶部。校验失败时可聚焦错误摘要，并让摘要链接到具体字段。

验收时拔掉鼠标，从地址栏开始完成核心任务，记录每次 Tab 的位置；同时用屏幕阅读器检查可访问名称。焦点顺序设计的目标不是“能 Tab 到所有东西”，而是让用户始终知道自己在哪里、下一步会去哪里。
