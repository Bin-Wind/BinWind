# 批量操作部分失败：逐项说明结果并支持重试

批量删除、导入或授权很少只有“全部成功”和“全部失败”。权限变化、网络错误或数据冲突可能让十项中七项成功。只弹出“操作失败”会迫使用户猜哪些需要重做，盲目重试又可能重复成功项。

## 结果要对应到对象

提交前显示选择数量、操作范围和不可逆影响。完成后给出总览：成功、失败、跳过和仍在处理中各多少项；失败项保留名称、稳定 ID、简明原因和可执行建议。成功项可从当前列表移除，但应能在结果面板中查到。

“重试失败项”必须只提交失败集合，并带幂等键。若错误不可重试，例如权限不足或字段格式错误，按钮应改为“查看权限”或“修正数据”，不能制造无效循环。

## 处理状态变化

长任务需要进度和取消语义：取消是停止尚未开始的项目，还是尝试回滚已成功项目，必须说清楚。页面刷新后应能用任务 ID 恢复状态，而不是回到一个不确定的加载动画。

验收用例至少包含单项失败、首项失败、末项失败、网络中断和结果回调重复。批量操作的可信感来自逐项可核对，而不是一个颜色鲜艳的总提示。
