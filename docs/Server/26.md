# systemd 服务管理与故障排查

在 Linux 上长期运行自建程序时，systemd 可以统一处理启动、重启、日志和依赖关系。不要用 `nohup` 加后台符号代替正式服务管理。

## 创建服务单元

假设程序位于 `/opt/demo/app.py`，创建 `/etc/systemd/system/demo.service`：

```ini
[Unit]
Description=Demo web service
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=demo
Group=demo
WorkingDirectory=/opt/demo
ExecStart=/opt/demo/.venv/bin/python /opt/demo/app.py
Restart=on-failure
RestartSec=3
EnvironmentFile=-/etc/demo/demo.env
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

`EnvironmentFile` 前的减号表示文件缺失时不阻止启动。敏感变量文件应限制权限，且不要把密钥直接写进 unit。

## 加载与操作

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now demo.service
systemctl status demo.service
journalctl -u demo.service -n 100 --no-pager
```

修改 unit 后必须 `daemon-reload`。查看本次启动日志可用 `journalctl -u demo.service -b`，实时跟踪加 `-f`。

## 排错顺序

先看 `systemctl status` 的退出码和最近日志，再核对 `User` 是否有目录权限、`ExecStart` 是否为绝对路径、工作目录与环境变量是否齐全。不要用无限快速重启掩盖启动失败；设置退避，并让监控对连续失败告警。

服务应监听关闭信号并在 systemd 的停止超时内释放连接。完成后用普通服务用户执行一次同样命令，最容易发现“手工能跑、服务不能跑”的环境差异。
