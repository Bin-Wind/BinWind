# 容器化应用备份与恢复演练

镜像和 Compose 文件可以重建应用，但数据库、上传文件与密钥配置不能从镜像自动恢复。可靠备份必须围绕数据一致性、异地副本和可验证恢复设计。

## 先做数据清单

逐个服务标记数据来源：数据库、命名卷、宿主机挂载目录、对象存储和外部 SaaS。缓存通常无需备份，但要确认它不是唯一数据源。配置可以进版本库，密钥则应进入独立秘密管理系统。

## 数据库使用逻辑备份

以 PostgreSQL 为例：

```bash
docker compose exec -T db pg_dump -U app --format=custom appdb > appdb.dump
test -s appdb.dump
```

恢复到隔离数据库验证：

```bash
createdb restore_check
pg_restore --exit-on-error --no-owner --dbname=restore_check appdb.dump
```

不要在生产库上测试恢复。不同数据库有不同一致性机制，直接压缩正在写入的数据目录可能得到不可用副本。

## 定义 RPO 与 RTO

RPO 表示最多能接受丢失多久的数据，决定备份频率；RTO 表示多快恢复服务，决定自动化与预热程度。两者都应由业务影响决定。

备份至少保留一份与生产故障域隔离的副本，并启用加密、访问审计与保留策略。每次演练记录备份时间、恢复耗时、校验结果和缺失步骤。只有成功恢复并通过抽样查询的备份，才算真正可用。
