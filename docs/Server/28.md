# Web 服务零停机发布实战

零停机的关键不是“进程启动得快”，而是新旧版本能在一段时间内同时工作，并由负载均衡只把流量发给已就绪实例。

## 就绪与存活分开

存活检查回答“进程是否需要重启”，就绪检查回答“实例能否接收流量”。就绪接口应验证关键初始化完成，但不要每次执行昂贵的全链路查询。

一个典型发布顺序：

1. 启动少量新实例，不立即接流量。
2. 完成迁移兼容检查、预热缓存和就绪探测。
3. 逐步把流量切给新实例并观察错误率与延迟。
4. 旧实例停止接收新连接，完成在途请求后退出。
5. 保留可快速回切的上一版本。

## 数据库向后兼容

采用“扩展—迁移—收缩”：先添加新字段或新表，让新旧代码都能工作；再回填数据并切换读取；确认旧版本不再使用后，才删除旧结构。发布代码同时执行破坏性迁移，会让回滚失去意义。

## 长连接与任务

WebSocket 需要客户端自动重连和版本兼容；消息消费者关闭前应停止拉取新任务，并完成或归还当前消息。为写操作提供幂等键，避免重试造成重复副作用。

发布前用脚本验证健康端点、关键业务请求和回滚路径。观察窗口至少覆盖足够请求量，不能仅因五分钟无报错就全量。真正的零停机来自兼容性与排空机制，而非单个部署命令。
