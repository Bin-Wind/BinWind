# SSH 服务加固：从密钥登录到最小权限

SSH 加固的核心是减少可尝试的入口、限制登录身份，并确保修改失败时仍能恢复。操作前保持一个已登录会话，不要先关闭现有连接。

## 先验证密钥

在新终端确认密钥登录成功，再编辑 `/etc/ssh/sshd_config` 或发行版的片段目录：

```text
PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
AllowUsers deploy
```

若仍依赖密码，不要提前关闭密码登录。`AllowUsers` 只列出确需远程访问的账号；日常运维使用普通用户与 `sudo`，不要直接登录 root。

## 校验后重载

```bash
sudo sshd -t
sudo systemctl reload ssh
```

部分系统服务名是 `sshd`。先用 `sshd -t` 检查语法，再重载而非重启。随后从另一终端建立新连接，确认成功后再退出旧会话。

## 继续收紧

限制安全组或防火墙来源地址，安装安全更新，并监控认证失败。改端口只能减少扫描噪声，不能代替密钥和访问控制。私钥应设置口令并妥善备份；人员离开时删除其公钥，同时检查自动化账号和跳板机权限。
