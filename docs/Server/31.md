# Web 服务容量规划：从单机压测到扩容阈值

容量规划不是猜“需要几台机器”，而是把目标流量、延迟、错误率和资源余量关联起来。先定义峰值请求、典型请求组合和服务等级目标。

## 用利用率估算起点

若单实例在可接受延迟下稳定处理 120 请求/秒，目标峰值为 500 请求/秒，并希望最高只用到 70% 容量，则初始估算为：

```python
import math

peak_rps = 500
safe_rps_per_instance = 120 * 0.70
print(math.ceil(peak_rps / safe_rps_per_instance))  # 6
```

这只是起点，不能替代整链路压测。数据库连接、缓存命中率和第三方限额往往先成为瓶颈。

## 设计压测

请求比例应接近真实流量，测试包含预热、阶梯升压、稳定阶段和突增。记录 p50/p95/p99 延迟、错误率、吞吐、CPU、内存、连接池与队列长度。压测环境和数据规模与生产差异必须写进结论。

## 扩容与降级

扩容阈值用持续窗口而非瞬时尖峰，并考虑新实例启动时间。预留单节点故障和发布期间的余量。即使能扩容，也要为下游过载准备限流、超时、缓存和非核心功能降级。
