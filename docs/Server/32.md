# logrotate 日志轮转：控制磁盘占用又保留历史

服务持续写单个日志文件，会让磁盘最终耗尽；直接清空又失去排障证据。`logrotate` 可以按时间或大小归档、压缩并清理旧日志。

## 一份可审查的配置

在 `/etc/logrotate.d/myapp` 中为应用单独配置：

```text
/var/log/myapp/*.log {
    daily
    rotate 14
    maxsize 50M
    compress
    delaycompress
    missingok
    notifempty
    create 0640 myapp adm
    sharedscripts
    postrotate
        systemctl kill -s HUP myapp.service >/dev/null 2>&1 || true
    endscript
}
```

应用必须在轮转后重新打开日志文件，HUP 是否有效取决于程序实现。若应用不支持，应改用它自己的日志轮转，谨慎使用 `copytruncate`，因为复制与截断之间可能丢失少量日志。

先运行 `logrotate -d /etc/logrotate.conf` 预览，再用测试环境验证权限、文件所有者和信号行为。监控日志目录与整个分区剩余空间；轮转能控制正常增长，无法解决异常日志风暴。
