# Nginx 上游健康与失败切换：避免把请求送给坏实例

多实例部署只有在代理能识别故障时才真正提高可用性。开源 Nginx 常用被动健康检查：真实请求失败达到阈值后，暂时避开该上游。

```nginx
upstream api_backend {
    least_conn;
    server 10.0.0.11:8080 max_fails=3 fail_timeout=20s;
    server 10.0.0.12:8080 max_fails=3 fail_timeout=20s;
    keepalive 32;
}

server {
    location /api/ {
        proxy_pass http://api_backend;
        proxy_connect_timeout 2s;
        proxy_read_timeout 15s;
        proxy_next_upstream error timeout http_502 http_503 http_504;
        proxy_next_upstream_tries 2;
    }
}
```

连接超时要短于用户请求期限，重试次数必须有限。默认只安全重试幂等请求；带写入副作用的请求若已到达上游，代理重试可能制造重复数据。

应用健康接口应快速检查“能否服务”，但不要每次执行昂贵的全依赖查询。发布时先从负载均衡摘除实例，等待存量请求结束，再停止进程。用故障演练确认单实例退出时延迟和错误率符合预期。
