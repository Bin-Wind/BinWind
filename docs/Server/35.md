# journald 日志保留：在可追溯与磁盘上限间取平衡

systemd-journald 会收集服务标准输出、内核与系统日志。若没有明确保留策略，服务器可能因日志耗尽磁盘；限制过小又会在事故调查前丢失证据。

## 先确认当前占用

```bash
journalctl --disk-usage
journalctl --list-boots
journalctl -u nginx.service --since "24 hours ago"
```

在 `/etc/systemd/journald.conf.d/retention.conf` 中使用独立覆盖文件：

```ini
[Journal]
Storage=persistent
SystemMaxUse=2G
SystemKeepFree=1G
MaxRetentionSec=14day
```

创建目录与文件后执行 `sudo systemctl restart systemd-journald`，再用 `systemd-analyze cat-config systemd/journald.conf` 核对生效配置。上限是多条件共同作用，并不保证精确保留 14 天。

## 清理前先留证

需要紧急释放空间时，可先导出事故窗口，再执行 `journalctl --vacuum-size=1G` 或按时间清理。不要直接删除正在使用的 journal 文件。

监控 journal 占用、文件系统剩余空间和日志写入速率。关键审计日志应同步到独立远端存储，本机轮转不能承担唯一留存责任。服务若高频输出同一错误，应修复根因并合理限流，而不是只扩大配额。
