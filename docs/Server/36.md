# PostgreSQL 逻辑备份与恢复演练

备份成功日志不等于数据可恢复。`pg_dump` 适合单库逻辑备份和跨版本迁移，但真正的保障来自定期在隔离环境执行恢复。

## 生成可校验备份

```bash
pg_dump --format=custom --no-owner --file=app.dump appdb
sha256sum app.dump > app.dump.sha256
pg_restore --list app.dump > app.dump.list
```

连接凭证不要写进命令历史，可使用权限受限的 `.pgpass`、短期凭证或密钥注入。备份文件可能包含个人与业务敏感数据，应加密、限制访问并设保留周期。

自定义格式支持并行恢复和选择对象。恢复到新建空库：

```bash
createdb appdb_restore
pg_restore --dbname=appdb_restore --jobs=4 --exit-on-error app.dump
```

## 验证业务而非只看退出码

恢复后检查关键表行数、外键、扩展、序列当前值和应用的只读烟雾测试。记录备份开始与结束时间、数据库版本、恢复耗时，以及可接受的数据丢失目标（RPO）和恢复时间目标（RTO）。

`pg_dump` 不是连续时间点恢复方案，也不自动覆盖角色和集群级配置。低 RPO 场景需结合物理备份与 WAL 归档，并同样演练恢复链。测试环境完成后按数据处理制度安全销毁。
