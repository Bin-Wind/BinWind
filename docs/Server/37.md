# 反向代理后的真实客户端 IP：只信任已知代理

应用部署在负载均衡或 Nginx 后，直接连接地址通常是代理 IP。盲目信任客户端提交的 `X-Forwarded-For`，攻击者就能伪造来源，绕过限流或污染审计。

## 由边界代理重写请求头

最外层可信 Nginx 应覆盖而非保留来自公网的同名头：

```nginx
location / {
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_pass http://app;
}
```

若 Nginx 前还有受控负载均衡，应使用 realip 模块，只为其明确网段配置 `set_real_ip_from`，并设置正确的头与递归策略。不要信任所有地址段。

## 应用按代理跳数解析

应用框架的“trust proxy”必须匹配实际拓扑。读取转发链时从最近一跳向外，仅跨过可信代理；链条第一项不一定自动可信。

安全规则优先使用认证身份，而非 IP。若 IP 用于审计与风控，同时记录原始链、解析后的客户端地址和接入代理，并保护日志不被用户输入换行污染。部署变更后用直连伪造头、单层代理和多层代理三种测试验证。
