# systemd 服务沙箱：逐项收紧进程权限

服务以普通用户运行只是第一步。systemd 可以限制文件系统、内核能力、临时目录和设备访问，把进程被利用后的影响范围压小。

## 从观察模式开始

先用 `systemd-analyze security your.service` 查看建议，再按真实依赖逐项启用：

```ini
[Service]
User=myapp
Group=myapp
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/myapp /var/log/myapp
CapabilityBoundingSet=
RestrictSUIDSGID=true
```

`ProtectSystem=strict` 会把大部分文件系统设为只读，必须用 `ReadWritePaths` 明确开放写目录。绑定低端口可交给反向代理，避免给应用额外 capability。

每增加一项都重启服务并走一遍启动、写文件、日志、升级和关停流程。查看 journal 中的权限拒绝，不要为图省事直接恢复 root。部署工具、备份任务和主服务可能需要不同权限，应拆成独立 unit，而不是共用一个过宽身份。
