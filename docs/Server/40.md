# DNS 切换演练：用低 TTL 和回退记录降低风险

域名切换不是按下保存后全网立即生效。递归解析器、客户端和应用都可能缓存旧记录，TTL 之外还可能存在连接复用。

## 切换前同时验证新旧端点

提前一个以上旧 TTL 周期降低记录 TTL；若临时改低后立即切换，旧缓存仍会按原 TTL 存活。新端点先用 Host 头或测试域名验证证书、路由、健康检查和真实业务请求。

```bash
dig example.com A +noall +answer
curl --resolve example.com:443:203.0.113.10 https://example.com/health
```

切换时记录旧值、新值、变更时间和回退条件，并保持旧服务可用至少覆盖缓存窗口。分别从多个公共解析器和业务地域检查，但不要把某一个查询结果视为全球状态。

确认错误率、证书、日志和核心交易稳定后再下线旧端点，并把 TTL 恢复为日常值。若同时变更 CDN、证书和应用版本，故障时难以定位；尽量拆成可独立回退的步骤。
