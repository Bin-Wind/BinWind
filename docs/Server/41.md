# Linux OOM 排查：从被杀进程回到内存压力来源

进程突然消失且无应用异常时，先检查是否触发内核 OOM。不要只重启服务；需要确认是持续泄漏、瞬时峰值，还是容器限制过低。

~~~bash
journalctl -k --since "-1 hour" | grep -Ei "out of memory|killed process|oom"
cat /proc/meminfo | head
ps -eo pid,ppid,comm,rss,vsz --sort=-rss | head
~~~

内核日志关注被杀 PID、oom_score_adj、cgroup 和当时内存信息。容器内看到的 free 可能与 cgroup 限额不同，应同时读取平台指标。区分匿名内存、页缓存、共享内存与 swap 活动，再关联发布、流量和批任务时间线。止损可限流或降低并发；扩容不能替代泄漏修复。为服务设置合理限制、告警和可复现压测。
