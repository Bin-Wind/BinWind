# 文件描述符耗尽：从 Too many open files 找到泄漏

服务出现 Too many open files 时，不要先把上限无限调大。文件描述符同时用于文件、套接字、管道和监控句柄，耗尽往往意味着连接未关闭或并发失控。

~~~bash
pid=1234
cat /proc/$pid/limits | grep -i 'open files'
ls /proc/$pid/fd | wc -l
lsof -nP -p "$pid" | awk '{print $5}' | sort | uniq -c | sort -nr | head
~~~

先确认进程当前数量、软硬限制和描述符类型，再按时间观察增长速度。大量 ESTABLISHED、CLOSE_WAIT 或重复路径分别指向不同问题；只看总数不足以定位。修复代码中的关闭路径、连接池上限或客户端超时后再评估合理限额，并让 systemd 与容器配置保持一致。

告警应同时关注使用量和上限比例。提高限制只能提供排查窗口，泄漏存在时最终仍会耗尽系统级资源。
