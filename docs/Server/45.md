# Nginx 请求 ID：串起代理与应用日志

一次请求经过负载均衡、网关和应用后，仅靠时间戳很难关联。入口生成或接收请求 ID，并在可信边界内向下游传递，可以把同一次调用的日志串起来。

~~~nginx
map $http_x_request_id $request_id_safe {
    default $request_id;
    ~^[A-Za-z0-9._-]{1,64}$ $http_x_request_id;
}

proxy_set_header X-Request-ID $request_id_safe;
add_header X-Request-ID $request_id_safe always;
log_format traced '$request_id_safe $remote_addr $request $status $request_time';
~~~

来自公网的 ID 必须限制字符和长度，或直接在边缘覆盖，防止日志注入与超长字段。应用日志用结构化字段保存同一值，下游调用继续传递；异步任务则记录父请求与任务自身标识。

请求 ID 不是身份凭证，也不能代替分布式追踪。日志中仍需控制个人信息，并设置采样、保留和访问权限。
