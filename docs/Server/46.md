# 容器中的 PID 1：正确接收停止信号并回收子进程

容器停止时运行时通常先向 PID 1 发送 SIGTERM。若入口使用 shell 包裹且没有 exec，应用可能收不到信号，直到宽限期结束被强制终止。

~~~sh
#!/bin/sh
set -eu

# 完成必要初始化后，让应用替换 shell 成为 PID 1
exec node server.js
~~~

应用收到 SIGTERM 后停止接收新请求、等待在途任务、关闭连接池并在有限时间内退出。若确实需要管理多个子进程，应使用能转发信号并回收僵尸进程的轻量 init，或把服务拆成独立容器。

在预发布环境执行真实 stop，观察应用日志、退出码和耗时；kill -9 不会触发清理。就绪探针应先转为失败，让负载均衡停止送流，再开始关闭，避免优雅退出窗口内继续接收新流量。
