# systemd 启动限流：阻止失败服务无限重启

`Restart=always` 能提高可用性，但配置错误或依赖永久失效时会形成高速重启循环，刷满日志并持续消耗资源。systemd 的启动限流可以在单位时间内失败过多后停止尝试。

~~~ini
[Unit]
Description=Example worker
StartLimitIntervalSec=60
StartLimitBurst=5

[Service]
ExecStart=/opt/example/bin/worker
Restart=on-failure
RestartSec=5s
~~~

这里允许 60 秒窗口内最多 5 次启动，失败后每次至少等待 5 秒。实际值应大于服务正常启动时间，并结合依赖恢复速度设置。`Restart=on-failure` 不会在干净退出时重启，比无条件重启更符合多数后台任务。

排查时使用 `systemctl status example` 和 `journalctl -u example --since today` 找到首次错误，不要只看最后一次“start request repeated too quickly”。修复原因后运行 `systemctl reset-failed example` 再启动。

限流不是健康检查替代品。服务若启动成功后内部失去功能，还需要应用探针、指标和告警；同时避免让探针过于激进地制造另一种重启循环。
