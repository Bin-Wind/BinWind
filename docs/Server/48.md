# Nginx 上游长连接：复用连接也要控制边界

反向代理频繁新建到应用的 TCP 连接会增加握手与端口压力。Nginx 可在每个 worker 中缓存一部分空闲上游连接，后续请求直接复用。

~~~nginx
upstream api_backend {
    server 127.0.0.1:9000;
    keepalive 32;
    keepalive_requests 1000;
    keepalive_timeout 60s;
}

server {
    listen 80;

    location /api/ {
        proxy_pass http://api_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_connect_timeout 2s;
        proxy_read_timeout 15s;
    }
}
~~~

`keepalive 32` 是每个 worker 缓存的空闲连接数，不是总连接上限，也不会限制正在使用的连接。后端仍需设置自己的最大连接数、请求期限与过载保护。连接复用数量过大反而可能占住后端资源。

上线前确认上游支持持久连接，并让代理的空闲超时短于后端强制关闭策略，减少刚取出就被对端关闭的连接。观察新建连接率、上游连接总数、502/504 和尾延迟，再逐步调整，而不是仅凭并发量套公式。
