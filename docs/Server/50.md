# Nginx 配置原子发布：先测试，再替换，最后平滑重载

直接编辑正在使用的配置文件，容易留下半写入内容；修改后立刻重启，又可能把语法错误变成停机。稳妥流程是生成候选文件、静态检查、原子替换，再执行平滑重载。

## 准备候选配置

将模板渲染到与目标文件同一文件系统的临时路径，设置正确属主与权限。不要在 shell 中用字符串拼接不可信变量生成指令。候选文件完成后先检查差异，确认没有意外删除 include 或证书路径。

```bash
sudo nginx -t -c /etc/nginx/nginx.conf.candidate
```

`nginx -t` 会检查候选主配置语法并尝试打开引用文件。候选配置中的相对路径仍受 Nginx prefix 影响，部署脚本应使用与生产一致的 prefix。通过后再以原子重命名替换目标；跨文件系统移动不保证原子性，因此临时文件应放在目标目录。

## 平滑重载不是完成信号

```bash
sudo systemctl reload nginx
sudo systemctl status nginx --no-pager
```

重载时旧 worker 会继续处理已有连接，新 worker 读取新配置。随后应检查错误日志、监听端口、证书与关键路由，用本机 Host 头探针确认虚拟主机命中正确。

## 回退

替换前保存上一个已验证版本及摘要。探针失败时恢复旧配置、再次运行 `nginx -t` 后重载。不要只把文件拷回去却忘记重载，也不要删除仍被旧 worker 使用的证书和日志路径。定期演练回退，才能证明备份不仅“存在”。
