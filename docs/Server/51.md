# Linux PSI：用压力停顿判断 CPU、内存与 IO 争用

负载高不一定意味着用户受影响；内存还没用完，也可能因回收和 IO 造成卡顿。Linux Pressure Stall Information（PSI）统计任务因 CPU、内存或 IO 资源不足而停顿的时间比例，可作为饱和度信号。

## 读取压力

```bash
cat /proc/pressure/cpu
cat /proc/pressure/memory
cat /proc/pressure/io
```

输出中的 `some` 表示至少有部分任务在等待；部分资源还会提供 `full`，表示所有非空闲任务同时停顿。`avg10`、`avg60`、`avg300` 是不同时间窗口的平均比例，`total` 是累计微秒数。字段是否存在取决于内核与资源类型。

## 与其他指标联读

CPU PSI 上升时查看运行队列和容器限额；memory PSI 上升时检查回收、swap、缺页和 OOM 事件；IO PSI 上升时结合设备延迟、队列深度和具体进程。PSI 指出“在等”，不会直接告诉你谁造成等待。

## 设计告警

先观察业务峰谷下的基线，再用持续时间与用户延迟共同设阈值。短促尖峰不一定需要告警，持续上升且请求尾延迟恶化才更可操作。容器环境可读取 cgroup 级压力文件，避免宿主机平均值掩盖单个服务。

变更前后同时比较 PSI、吞吐和延迟。若扩容降低 PSI 却没有改善用户指标，应继续检查锁竞争或外部依赖，不把相关性当作根因。
