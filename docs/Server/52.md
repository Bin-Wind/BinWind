# SSH known_hosts 轮换：更换主机密钥时不中断信任链

SSH 主机密钥证明“连接的是原来的服务器”。遇到 `REMOTE HOST IDENTIFICATION HAS CHANGED` 时直接删除整份 `known_hosts`，会失去对其他主机的校验，也可能掩盖中间人攻击。

## 计划内轮换

优先在旧密钥仍可信时发布新公钥指纹，通过配置管理、受保护的资产系统或 DNS SSHFP（配合经验证的 DNSSEC）等独立渠道分发。客户端先同时信任新旧密钥，服务器再启用新密钥，观察连接成功后才移除旧密钥。

```bash
ssh-keygen -F server.example.com
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

第二条应在服务器可信控制台上执行；不要从当前可疑连接里读取指纹再用它“验证自己”。

## 意外告警

先停止自动连接，确认是否发生重装、IP 复用、负载均衡变化或密钥轮换。通过云控制台、机房通道或管理员签名公告核对新指纹。只删除目标主机旧记录：

```bash
ssh-keygen -R server.example.com
```

随后在确认新指纹后重新连接。自动化环境应使用集中管理的 known_hosts 文件并审查变更，不应设置 `StrictHostKeyChecking=no`。

完成轮换后记录旧新指纹、批准人、启停时间与受影响别名。IP、短主机名和完整域名可能分别有记录，都要纳入验证。
