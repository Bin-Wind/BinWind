# systemd Drop-In：覆盖服务配置而不修改发行版文件

直接编辑 `/usr/lib/systemd/system` 或 `/lib/systemd/system` 下的服务文件，会让软件包升级覆盖本地修改。systemd 的 drop-in 可以只声明差异，并保留上游单元文件。

先查看实际加载来源和合并结果：

```bash
systemctl cat myapp.service
systemctl show myapp.service -p FragmentPath -p DropInPaths
```

使用 `systemctl edit myapp.service` 创建 `override.conf`。例如增加环境文件和重启间隔：

```ini
[Service]
EnvironmentFile=/etc/myapp/runtime.env
RestartSec=5s
```

某些列表型指令会累加。需要替换原来的 `ExecStart` 时，必须先用空值清空，再声明新命令：

```ini
[Service]
ExecStart=
ExecStart=/usr/local/bin/myapp --config /etc/myapp/config.toml
```

修改后运行 `systemctl daemon-reload`，用 `systemd-analyze verify` 和 `systemctl cat` 检查合并结果，再在维护窗口重启服务。不要把密钥直接写进单元文件或普通环境文件；敏感值应使用权限严格的凭据机制。

回退时删除目标 drop-in 文件并重新加载，而不是复制一份旧完整单元覆盖上游。把 override 纳入配置管理，并记录它依赖的上游指令，升级后复查是否仍有必要。
