# Linux ss 排障：从监听端口追到对应进程

端口不可达时，先确认服务是否真的监听、监听在哪个地址，再检查防火墙和上游网络。`ss` 直接读取内核套接字信息，通常比盲目重启服务更快定位问题。

```bash
sudo ss -lntp
sudo ss -lntp 'sport = :8080'
sudo ss -nt state established
```

`-l` 只看监听，`-n` 禁止名称解析，`-t` 查看 TCP，`-p` 显示进程信息。普通用户可能看不到其他进程详情。若服务只监听 `127.0.0.1:8080`，本机可访问但外部无法直连是预期行为；反向代理应连接本地地址。

## 按链路逐层验证

先在服务器上用目标地址访问，再从同网段和外部客户端测试。监听在 `0.0.0.0` 表示所有 IPv4 接口，并不等于防火墙已开放；`[::]` 的双栈行为还受系统配置影响。容器中的监听地址与宿主机发布端口也要分别检查。

连接大量堆积时，比较 `SYN-RECV`、`ESTAB`、`TIME-WAIT` 等状态，但不要仅凭某个数量判断故障。结合请求速率、应用日志、文件描述符和正常基线。把命令输出中的公网地址和进程参数脱敏后再分享到工单。
