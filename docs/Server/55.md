# systemd-tmpfiles：按规则创建并清理应用临时目录

应用把临时文件长期堆在 `/tmp` 或自建目录，容易留下过期数据；启动脚本中随手 `rm -rf` 又可能误删仍在使用的文件。`systemd-tmpfiles` 用声明式规则管理目录、权限和基于年龄的清理。

在 `/etc/tmpfiles.d/myapp.conf` 中为应用定义专用目录：

```text
d /var/tmp/myapp 0750 myapp myapp 7d
```

`d` 表示目录存在时保留并校正基本属性，不存在时创建；最后的 `7d` 作为清理年龄参数。不同规则类型的删除语义并不相同，编写前应查看本机 `tmpfiles.d(5)`，不要从示例推断所有字段。

先检查配置，再分别执行创建和清理：

```bash
systemd-tmpfiles --cat-config
sudo systemd-tmpfiles --create /etc/tmpfiles.d/myapp.conf
sudo systemd-tmpfiles --clean /etc/tmpfiles.d/myapp.conf
```

## 把活跃文件与缓存分开

正在写入的任务文件不应仅靠访问时间保护，因为挂载选项和应用行为会影响时间戳。为活跃任务使用独立目录和显式状态，完成后再移动到可按年龄清理的位置。涉及会话、上传和审计材料时，还要满足业务保留规则。

上线前在测试目录验证所有者、符号链接和清理范围，并监控文件数量与磁盘占用。tmpfiles 负责生命周期执行，应用仍应在正常成功与失败路径主动清理自己的文件。
