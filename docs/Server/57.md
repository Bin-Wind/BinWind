# findmnt --verify：修改 fstab 后先做静态检查

`/etc/fstab` 的设备、挂载点或选项写错，可能让下次启动进入紧急模式。保存后可先用 `findmnt` 做语法和可用性检查。

```bash
sudo findmnt --verify --verbose
```

检查前先备份文件，并用 `lsblk -f` 或 `blkid` 核对 UUID 与文件系统类型。挂载点目录必须存在，网络挂载还要考虑网络就绪顺序和失败是否应阻塞启动。

静态验证通过后，使用明确目标测试新增条目，例如 `sudo mount /data`，再用 `findmnt /data` 确认来源、文件系统与实际选项。不要在远程机器上直接执行无目标的 `mount -a` 而没有备用会话或控制台，它可能挂起在不可达网络存储上。

验证只能发现部分配置问题，不能证明设备在重启阶段一定可用。重要主机应在维护窗口做一次可恢复的重启演练，并保留带外访问方式与原配置副本。
