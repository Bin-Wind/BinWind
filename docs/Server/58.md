# systemd-analyze verify：部署前检查服务单元

systemd 单元文件中的未知指令、错误依赖和无效可执行路径，常在发布后才暴露。`systemd-analyze verify` 可在启动服务前做静态检查。

```bash
systemd-analyze verify ./myapp.service
```

若单元引用同目录下的其他自定义 unit，可把相关文件一起传入。检查输出可能包含系统中既有单元的警告，应区分本次新增问题，不要把所有 stderr 简单当成同一故障。

安装后执行 `sudo systemctl daemon-reload`，再用 `systemctl cat myapp.service` 确认主文件与 drop-in 的最终合并结果。测试 `ExecStart` 使用绝对路径、运行用户能访问工作目录，环境文件存在且权限合适。

静态检查无法覆盖网络、密钥、端口占用和应用启动后的健康状态。先在预发运行，通过 `systemctl show` 和 journal 核对退出码、重启策略与资源限制，再逐步发布到生产。
