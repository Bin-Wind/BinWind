# journalctl 按启动批次排障：区分本次与上次开机

服务在重启后恢复正常，最有价值的错误可能留在上一次启动周期。`journalctl` 能按 boot ID 切分日志，避免把多次开机记录混在同一时间范围里。

## 先列出启动记录

```bash
journalctl --list-boots
```

列表中的 `0` 表示当前启动，`-1` 是上一次，依次向前。查看上一次启动的内核错误：

```bash
sudo journalctl -b -1 -k -p warning..alert
```

查看当前启动中某服务的完整记录：

```bash
sudo journalctl -b 0 -u nginx.service --no-pager
```

`-b` 先限定启动批次，`-u` 再限定单元；结合 `--since` 与 `--until` 可缩小时间。排查异常重启时，重点看上一批次末尾：

```bash
sudo journalctl -b -1 -e
```

## 理解“没有日志”

若 `--list-boots` 只有当前记录，可能是日志未持久化、已轮转，或系统根本没有使用 systemd journal。检查 `/etc/systemd/journald.conf` 的存储策略与磁盘占用，不要因为查询为空就判断“之前没有错误”。

导出日志时保留 boot ID、主机名和准确时区，并对令牌、请求正文等敏感内容脱敏。`journalctl` 查询是只读的；不要为了“重新产生错误”直接重启生产服务，先保存当前证据并确认影响范围。
