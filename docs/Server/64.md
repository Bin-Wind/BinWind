# timedatectl 校时检查：先确认同步状态再排查时间漂移

证书突然失效、日志顺序混乱或分布式任务重复执行，都可能与系统时间有关。排障第一步不是手动改时钟，而是确认时区、系统时钟和时间同步服务的状态。

```bash
timedatectl status
```

重点查看 `Local time`、`Universal time`、`Time zone`、`System clock synchronized` 和 `NTP service`。业务服务器通常用 NTP 保持时钟，并让日志明确包含时区；展示给用户的本地时间再由应用层转换。

若系统使用 systemd-timesyncd，可查看更详细状态：

```bash
timedatectl timesync-status
journalctl -u systemd-timesyncd --since '1 hour ago'
```

不同发行版可能使用 chrony、ntpd 或云厂商代理，此时 `timedatectl` 只给出部分信息，应查询实际服务，不要同时启用多个时间守护进程互相调整。

## 不要贸然跳时

生产机手动执行 `date` 可能让数据库、租约和日志产生时间倒退。先记录当前偏差、同步源、最近重启和虚拟化环境，再按所用守护进程的文档处理。大偏差是否允许步进校正还是只能缓慢调整，取决于业务容忍度。

时钟同步不等于应用时区正确。容器、JVM 和数据库还可能各自配置时区。用带 UTC 偏移的时间戳贯穿链路，并用请求 ID 排序事件，能降低只依赖墙上时钟带来的歧义。
